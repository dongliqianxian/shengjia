## 七种 reader 布局

```
代号  维度  数据      描述符头                  轴位置                       行距
────────────────────────────────────────────────────────────────────────────────────
 A    2D   int16有符号 [cols][rows][右移位数]    X @ desc+6                  cols*2+2
                       Y 轴嵌在每行开头(2字节)
 B    3D   int16       [dim1][dim2][dim3]       轴1 @ desc+8                 cols*2
                                               轴2 @ desc+8+2*d1             (数据打包)
                                               轴3 @ desc+8+2*d1+2*d2
                                               数据 @ 轴3之后
 C    2D   uint16      [cols][rows]             X @ desc+4                   cols*2+2
                       Y 轴嵌在每行开头(2字节)
 D    1D   uint8       [u8 cols]                X @ desc+1 (u8)              数据 @ desc+1+cols
 E    1D   int16       [cols][右移位数]          X @ desc+4                   数据 @ desc+4+cols*2
 F    2D   uint8       [u8 cols][u8 rows]       X @ desc+2 (u8)              cols+1
                       Y 轴嵌在每行开头(1字节)   ★ 输出 = 单元值 × 256
 G    1D   uint16无符号 [cols][?]                X @ desc+4                   数据 @ desc+4+cols*2
```

**要点**

- A / C / F 的「数据地址」指向**第一行的 Y 轴表头**，真正的单元在其后 2（F 是 1）字节。
  工具（ECM Titanium）通常报表头地址，用户的 WinOLS 定义通常报单元地址——差 2，别当成对不上。
- **A 和 E 的描述符里直接带右移位数**，是 Q 格式的一半答案，白送。
- **B 的 `desc+4` 是 dim3，不是移位量。** 这是区分「三维平面」和「真副本」的唯一硬判据。
- **F 的输出是单元值 ×256**（例程内部对轴做 `shl 8`、对 Δ 做 `shr 8`，净效果是输出放大 256）。
  忘了这条会让所有 8 位表的换算差 256 倍。

## 怎么从反汇编认出布局

看例程开头十几条就够：

**A 型**（行内嵌 Y 轴、带移位量）
```
ld.h  6[r8], r10        ; X 轴首元素 → X 在 desc+6
ld.hu 0[r8], r9         ; cols
shl   1, r9             ; cols*2
addi  4, r8, r11
add   r9, r11           ; desc+4+cols*2 = X 轴末元素
...
add   2, r9             ; ★ 行距 = cols*2 + 2
ld.hu 2[r8], r18        ; rows
mulh  r9, r18           ; rows × 行距
...
尾部:
ld.hu 4[r8], r11        ; ★ 移位量
bp    +                 ; 结果为正 → 直接移
subr  r0, r10 / shr r11, r10 / subr r0, r10    ; 保号的算术右移
jmp   [lp]
```

**B 型**（三维）—— 头三行就露馅
```
ld.hu 0[r9], r14  /  ld.hu 2[r9], r15  /  ld.hu 4[r9], r16    ; dim1 dim2 dim3
mulhi 2,...×3
ld.h  8[r9], r10  ; cmp r10, r6   ; 用 r6 夹轴1
...               ; cmp r10, r7   ; 用 r7 夹轴2
...               ; cmp r10, r8   ; ★ 用 r8 夹轴3 —— 第三个入参是第三轴输入
```

**C 型**：`ld.hu 4[r8], r10` + `addi 2, r8, r11` ⇒ X 在 desc+4，且用 `ld.hu`（无符号）

**D / F 型**（8 位）：`ld.bu` + 对轴值 `shl 8`

**E / G 型**（1D）：描述符在 **r7**（E）或 r7（G），只搜一条轴、只做一次插值

## 定点算术原语

这三个小函数会被上百处调用，**是给未知表定换算的钥匙**：

```
f(a, b, n) = (a × b) >> n              16 位定点乘（mulh + sar）
g(a, b, n) = sat32((a × b) >> n)       64 位中间、32 位饱和（mul + 跨字右移 + 溢出钳位）
h(a, b)    = sat16(a − b)              饱和减（只吃两个参数）
```

**第三个参数 `n` 就是那一步的 Q 格式。** 常见 13/14/15/16 = ÷8192/16384/32768/65536
（即 8192/16384/32768/65536 代表 1.0）。

怎么用：沿数据流走一遍——某表输出送进哪个原语、`n` 是多少、另一个操作数单位已知吗——
就能把该表的物理换算反推出来。

**认它们的样子**：
- `mulh` + `sar r8, r10` + `jmp [lp]`，四条指令 ⇒ 16 位定点乘
- `movea 0x3F, r0, r1; cmp r1, r8; bnh` 开头（n>63 返回 0）+ `mul` + 跨字移位 ⇒ 64 位版
- `sub` + `addi 0x8001` / `movea 0x7FFF` / `movea 0x8000` ⇒ 饱和减

**旁路分支的硬编码值揭示归一化基准**：若某处 `movea 0x4000, r0, rX` 作为「不查表时的默认值」，
说明该表输出是 Q14（16384 = 1.0）。

## 丰田 DENSO 定点约定

跨车型大概率一致，**但每台车仍需各自验证**（尤其转速，两档并存）：

```
扭矩      raw / 32 = Nm
转速      100/2^n 家族，两档并存：
            ×0.78125  (=100/128)   —— 常见于 18×25 / 17×25 这类扭矩·转速表的行头
            ×0.390625 (=100/256)   —— 常见于正扭矩模型、限制器曲线
角度      × 0.3125                 —— VVT 相位、点火
λ         raw / 128
百分比    / 128 (0–130%) 或 / 512 (0–100%)
AFR 轴    raw / 1024               —— 12288 = 12.0，14950 = 14.6（加浓/化学计量比两个平面）
```

**验证套路**：把候选因子代进去，看断点是不是全整数；若多个因子都给整数（断点全是 256 倍数时
必然如此），换物理形状锚点——例如正扭矩模型的零负荷列应当随转速单调变负、并在某转速穿零
（那是摩擦/泵气曲线），再拿满负荷峰值对原厂标称扭矩。

## V850E/RH850 反汇编陷阱

**① `LD.BU` 会被误判成 `JARL`**
op6 = 0x3C/0x3D 时，若第二个 halfword 的 **bit0 = 1**，那是 `LD.BU disp16[r1], r2`，**不是 JARL**。
（JARL 的位移最低位恒为 0，因为指令 2 字节对齐。）
症状：出现负地址或奇数地址的跳转目标。

**② 对齐自检**
一个函数必须以 `jmp [lp]` 结束 —— halfword `0x007F`。反汇编到函数尾却落不到它，说明中途对齐错了。
把这条做成解码器的断言，能自动抓出所有长度判断错误。

**③ CMOV 的两种形态**（op6=0x3F）
```
hw2 & 0x07FF ∈ [0x0300,0x031F] 且偶  ⇒ CMOV cccc, imm5, r2, r3
hw2 & 0x07FF ∈ [0x0320,0x033F] 且偶  ⇒ CMOV cccc, r1,   r2, r3
条件码 = (key − base) >> 1
```
限制器链里到处是它（取 min/max），不解出来会看不懂仲裁逻辑。

**④ `DIVQ`**（RH850 扩展）hw2 & 0x07FF = 0x02FC，操作数结构同 DIV。插值例程末尾用它做除法。

**⑤ CMP 的方向**
`cmp reg1, reg2` 算的是 **reg2 − reg1**。配合 CMOV 判 min/max 时方向搞反，整个仲裁逻辑就读反了。
