# DENSO / RH850 全表清单（代码驱动）

## 为什么这套方法值得先做

DENSO RH850 的标定表是**自描述对象**：代码只持一个描述符指针，由通用 reader 例程解析头部
（列数、行数、移位量、轴位置）。这意味着——

> **找到 reader → 扫出所有调用者 → 一次拿到所有走该路径的表，维度和轴由 ECU 自己的解析逻辑给出。**

比逐张盲扫形态强得多：盲扫给的是"候选 + 可信度"，这套给的是**代码事实**。在一台 1.5 MB
的丰田 ECU 上，这套流程从零扫出 1010 张已验证的表（对比：ECM Titanium 驱动 31 张、
用户手工 WinOLS 工程 85 张）。

**它不替代盲扫**：走指针表分派、或用 `movhi+movea` 装地址的表扫不到（见「已知缺口」）。
两者互补——本技能先把 80% 的表用代码钉死，剩下的交 `blind-map-finder`。

## 四个阶段

### 阶段 1 — 平台识别与基址（不做这步后面全错）

```bash
python scripts/find_readers.py <bin> --recon
```

判据：
- 字符串 `RX-OSEK850` ⇒ Renesas V850 / RH850，**小端**
- 偏移 0 处 `80 07 xx xx` = `JR disp22`（复位向量）；`80 07 00 00` = `JR .`（未用中断向量，
  16 字节间距）⇒ **Flash 基址 = 0x00000000**，入口 = JR 的目标
- 熵分区：低熵尾部通常是填充/数据 Flash，不含标定

若字符串或向量对不上，**先停下**——不是这个平台，转 `multi-vendor-ecu-engine` 定核与字节序。

### 阶段 2 — 找 reader 例程

```bash
python scripts/find_readers.py <bin>
```

原理：扫全文件里 `MOV imm32, rX`（halfword `0x0620..0x063F`）后面近距离跟一条 `JARL` 的配对，
把 JARL 目标做直方图。**被几百个不同常数指向的目标就是 reader 候选**。

然后必须**逐个反汇编判定**——这一步不能省：

```bash
python scripts/v850dis.py <bin> 0x06590C 0x60
```

是 reader 的样子：读描述符头（`ld.hu 0[rN]` 取 cols）、算行距、二分/线性搜轴、插值、`DIVQ`。
**不是** reader 的样子（真实反例，都被几百个常数指向过）：
- `mov sp,ep` + `sst.b` + `andi 0x23/0x50/0x8C` + `tst1/set1/clr1` ⇒ **CAN 信号打包/解包**
- `andi 0xC000` 掩码 + gp 标志位测试 + 指针表索引 ⇒ **参数/句柄访问器**
- `stsr sr5` + `ei/di` 临界区 ⇒ **带中断锁的消息队列**

> 「有指针传给某函数」不等于「那函数是表读取器」。本轮曾据此高估 500 张，实际只有 237。

### 阶段 3 — 扫全表

确认 reader 的**布局**（见 `references/reader-layouts.md`），然后：

```bash
python scripts/map_inventory.py <bin> --reader 0x06590C=A --reader 0x066B10=B \
       --reader 0x065A80=C --reader 0x064DC4=D --reader 0x065444=E \
       --reader 0x0654C4=F --reader 0x064EB0=G -o tables_from_code.csv
```

脚本对每个「常数 + reader」配对做**结构校验**（维度合理、轴单调、整块落在文件内），
**只把通过校验的写进 CSV**——没验过的不进清单。

输出列：`描述符 / reader / 位宽 / 维度 / 数据地址 / 轴地址 / 轴原始值域 / 移位量或dim3 / 调用者数`

### 阶段 4 — 交叉验证与使用

拿清单去对已有定义（WinOLS 工程 / ECM Titanium / BitEdit）：

- **对得上** → 那条定义可信
- **对不上** → 重点看，多半是定义错了（或者工具的命名在骗人）
- **工具显示"[N] 份副本"而清单显示 dim3=N** → 那不是副本，是**三维表的 N 个平面**，改动必须整组同步

---

## 清单最有价值的三列

**`调用者数` = 免费的影响面评估。** 1 个 = 局部；4+ = 牵一发动全身。动手前先看这一列。

**`移位量`（reader A/E 的 `desc+4` / `desc+2`）= Q 格式的一半答案**，从描述符里直接读出来，
不用猜。另一半（常数偏置）在调用者代码里——见下。

**`dim3`（reader B）= 第三个轴的点数。** 这是区分「真副本 / 三维平面 / 跨模块拷贝」的唯一硬判据。

---

## 定换算：三段都要看

一张表的物理换算 = **表 + reader + 调用者**，缺一段就定不下来。

1. **表**：轴的整数刻度法（断点解成 0/10/20/…/520 ⇒ /32 = Nm）
   ⚠ **失效场景**：当所有断点都是 256 的倍数时，`/32 /64 /128 /256` 全给整数，判据无信息量。
   这时必须换**物理形状锚点**（如零负荷列随转速单调变负的摩擦曲线 + 峰值对照原厂标称扭矩）。
2. **reader**：描述符里的移位量。
3. **调用者**：常数偏置藏在这里。反汇编调用点，找 `addi 0xE700, r10, r10` 这类——
   本轮某正扭矩模型的 `−200 Nm` 偏置就是这么找到的，光看表永远解不出来。
   还要看**定点乘原语**：`(a×b)>>n` / `sat32((a×b)>>n)`，**第三个参数 n 就是那一步的 Q 格式**。

丰田 DENSO 常见约定（跨车型大概率一致，仍需各自验证）见 `references/reader-layouts.md`。

## 判断一张表「要不要改」

按强度排序，代码判据永远压过命名：

1. **输出被谁读**——扫该表结果所写入的 gp 变量。**写 N 次读 0 次 ⇒ 观测量**，改它零控制意义。
   扫描要覆盖 `ld.h`/`ld.hu`/`ld.w` 重叠/`ep` 重定基四种形式，并用一个已知高频变量做**对照组**
   证明扫描器有效。本轮据此判定一张被工具标为核心扭矩表的 map 完全不必改。
2. **整表恒定** ⇒ 被架高或中性化。`raw` 是 2 的整次幂（16384、8192）多为「设成满量程=不启用」；
   非 2 的幂（6432、160）更可能真标定过，且常是「中性值」（贡献被下游同量抵消）。
3. **调用者数**（见上）。
4. **命名** —— 最弱。工具的名字是第三方逆向，不是原厂真值。

## 已知缺口（要如实告诉用户）

按 `MOV imm32 + JARL` 配对扫，**扫不到**：

- 用 `movhi + movea` 组合装地址的
- 经**指针表分派**的（如「5 个换挡 × 14 个模式」这种二维索引查表组）
- 走本技能没解出的 reader 的
- **经全局基址寄存器 `gp`/`tp`/`ep` + 16 位位移访问的**——这类根本不构造地址，
  `MOV imm32` 扫描天生看不见。实测一台丰田 V850 的传动系标定全部走 `ld.h <disp>[tp]`，
  基址在复位路径里由 `mov 0xE010,tp` 装入一次。**这也是 Ghidra xref 会全部返回 0 的原因。**
  解锁流程见 `ghidra-ida-setup` §5；按已知物理量定位并证实交 `physical-constant-locator`。

本轮 12 个第三方定义的维度里，有 8 个在清单里零命中——**清单是「代码可达的表」，不是「文件里所有的表」**。
补漏走 `blind-map-finder`，但把它的轴单调性判据从「严格递增」放宽到「**非递减**」
（末尾有重复值的轴会被严格递增误杀——本轮因此漏了 70 张换挡曲线）。

## 边界

产出**代码证实的结构事实**，不产出：
- **功能名** —— 代码里没有字符串标签。判定交 `ecu-map-analysis`
- **完整 factor/offset** —— 只给移位量，常数偏置要跟调用者。换算表述交 `winols-scaling-converter`
- **字节读写 / 改 bin** —— 交 `denso-bin-engine`
- **checksum** —— 交 `checksum-crc-engine` 或 ECM Titanium Auto-Fix
- **修改方案** —— 交 `stage1-calibration-matrix`

有 A2L/DAMOS 时不必用本技能，改用 `damos-a2l-parser`；有 WinOLS 工程用 `winols-ols-parser`。
本技能的价值恰恰在**这些都没有**的时候。
