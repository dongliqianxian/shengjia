# Bosch ME7 KFMIRL/KFMIOP 扭矩链参考

## 适用边界

本参考用于 Bosch ME7 软件族中 KFPED、KFMIRL、LDRXN、KFMIOP、KFZWOP/2 与扭矩监控的分析路由。
以下名称和变量属于 `FAMILY-CONVENTION`：只有同 HW/SW/Cal ID 的 FR、A2L/DAMOS、代码引用或逐单元格
验证才能升级为 `VERIFIED`。论坛讨论可生成检查项，不能提供可直接写入的地址、百分比或阈值。

讨论来源：<http://nefariousmotorsports.com/forum/index.php?topic=970.0>

## 控制链

```text
踏板
  -> KFPED（踏板到请求扭矩）
  -> 请求扭矩/效率修正
  -> KFMIRL（请求扭矩到目标相对负荷）
  -> LDRXN 等负荷包络限制
  -> rlsol（请求负荷，变量名按版本确认）
  -> 节气门/增压/空气路径
  -> rl_w（实际相对负荷）
  -> KFMIOP（负荷到基础/最优扭矩侧模型）
  -> 点火、Lambda、损失和附件效率修正
  -> 估计/允许/最终扭矩
  -> ECU 扭矩监控、TCU 与 ESP/ASR 协调
```

关键纪律：

- `LDRXN` 常见为随转速变化的最大允许/请求负荷，不是通用转速限制器。
- `KFMIRL` 与 `KFMIOP` 是功能反函数，不是算术倒数，也不要求固定 `+x%/-x%`。
- KFMIOP 可在不同调用路径中由 `rl_w` 生成 `mibas`，由最大负荷侧变量生成 `mimax`；确切变量和调用
  路径必须按同版本定义确认。
- `rlmax/rlmx` 常表示最大允许负荷侧量，不等于当前驾驶员请求负荷；记录请求负荷优先寻找 `rlsol`。
- 模型往返检查先建立 ORI 基线；OEM 的储备、损失和插值可使 `F(G(T))` 不等于严格的 `T`。

## MAP 角色与证据检查

| 对象 | 常见角色 | 修改前必须确认 |
|---|---|---|
| KFPED | 踏板到请求扭矩 | 轴、模式/档位副本、低踏板与低转响应 |
| KFMIRL | 请求扭矩到目标负荷 | 请求轴、RPM 轴、输出负荷单位、效率修正入口 |
| LDRXN | RPM 对最大请求/允许负荷包络 | 是否实际限制 `rlsol`、温度/档位/保护修正 |
| KFMIOP | 负荷到基础/最优扭矩侧模型 | `rl_w/mibas` 与最大负荷侧调用、轴顶、实际负荷域 |
| KFZWOP/KFZWOP2 | 最优点火/效率计算参考 | 是否与 KFMIOP 共享负荷轴、模式和 Bank 副本 |
| KFMIZUFIL/KFMIZUOF 等 | ME7 监控/许可相关候选 | 同版本 FR 含义、使能条件、是否为监控包络或模型副本 |

标签相似不证明地址、角色或修改方向。对 `_UM`、Bank、模式、温度和监控镜像先查调用关系，不默认全部
一起改，也不默认全部不改。

## 轴扩展与共享轴

当新目标或实际负荷超过 KFMIOP 原厂负荷轴上限时，标记 `AXIS_REVIEW`，不要先改 Z 值掩盖钳位。

1. 记录 ORI 负荷轴、当前实际负荷和目标负荷范围。
2. 查找与该轴使用相同地址的所有 MAP；常见候选包括 KFZWOP、KFZWOP2、KFDZWOAGR 或其他效率表，
   但必须以当前文件共享地址为准。
3. 扩展时优先保留怠速、巡航和低负荷轴点；只在有证据的新高负荷域增加覆盖。
4. 对共享 MAP 按物理含义重新插值，检查单调性、边界斜率和过渡，不复制其他软件版本的轴值。
5. 未找齐共享对象或单位不明，状态为 `NO_EDIT / SHARED_AXIS_UNKNOWN`。

## 扭矩监控与干预

- 不把通用功能安全的 Level 1/2/3 直接等同于 ME7 文档中的扭矩干预阶段。
- 部分负荷通过点火快速微调扭矩可能是正常控制；目标不是消除全部干预。
- 节气门强制关闭、控制上限 DTC、limp、巡航持续振荡或独立安全监控触发属于停止信号。
- KFMIZUOF/KFMIZUFIL 全表写满、拍平，或把温度使能移出可达范围，默认判 `REJECT_MONITOR_DISABLE`。
- 合法目标域扩展如需同步独立监控包络，必须有同版本定义/代码证据，保留表形、诊断容差和故障反应。

## 下游扭矩接口：ESP/ASR 与 TCU 为什么对 KFMIOP 敏感

KFMIOP 不是"只喂给 KFMIRL 的配套逆表"。同一模型输出被多个下游同时消费：实际扭矩估算、最大允许
扭矩、扭矩监控，以及经扭矩广播供 ESP/ASR 与 TCU 协调。因此 KFMIOP 偏差不止影响本机驾驶性，会
沿 CAN 传导到车身稳定与变速箱——把 KFMIOP 往"好看的方向"改而不对齐真实扭矩，等于同时污染这两个
安全/传动接口。

ESP/ASR 减扭是**闭环升级**过程，不是一次到位，这解释了为什么错误 KFMIOP 会让减扭"变粗暴"：

1. 检测到打滑，ESP 按"当前扭矩"请求一个减扭量——这个"当前扭矩"来自 ECU 的 KFMIOP 侧估算。
2. 若估算偏差，首次减扭量与真实需求不匹配，轮胎继续打滑。
3. ESP 升级请求，ECU 以更大退角、关节气门甚至断油执行。

实车对照（证据等级 B，论坛实车观察）：过颠簸路面时，KFMIOP 错 → 动力被长时间切断；KFMIOP 对
→ 只闪一下 ESP 灯、动力轻微下降即恢复。**症状是"干预过猛/持续"，不是"轻微偏移"——因为闭环消费者
会把你的估算误差放大后再执行。**

TCU 侧同理：离合器油压、换挡扭矩协调、档位扭矩保护都按 ECU 报告的扭矩计算。估算失真或为绕限制
故意低报扭矩，可能造成离合器油压不足、换挡滑摩、扭矩协调错误、档位保护异常或扭矩监控 limp。

工程含义：KFMIOP 的验证标准**不止"本机不报错"**，还要求 ESP/ASR 与 TCU 的减扭/换挡响应平顺。
判 KFMIOP 是否合格必须把这两个接口纳入 LOG（见 LOG 路由的"下游"项）。

## 点火振荡的鉴别诊断

巡航/加速时看到点火角振荡，**不能直接判定"KFMIRL/KFMIOP 不匹配"**。点火角同时受动态爆震控制、
爆震学习、暖机点火修正、IAT 修正、扭矩结构目标点火、外部扭矩请求和怠速控制影响——多个系统都能
让点火角动。误把爆震/温度修正当成扭矩干预，会导向改 KFMIOP/KFMIRL 这个错方向。

判据（需同时记录并按时间对齐）：

```text
zwgru  基础点火来源
  -> zwbas  基础修正后的点火
  -> zwsol  扭矩结构要求的目标点火
  -> zwout/zwist  最终输出点火
（并列参考：dwkrz/wkrdy 等爆震减角；IAT、ECT 及其点火修正）
```

- 只有当 `zwout` 明显**跟随 `zwsol` 而偏离 `zwbas`** 时，才更支持"扭矩结构正在借点火干预扭矩"，
  此时才把线索指向扭矩模型（KFMIRL/KFMIOP 自洽性）。
- 若 `zwout` 的偏离能由 `dwkrz` 爆震减角或温度修正解释，则振荡与扭矩模型无关，改扭矩表是错方向，
  应转向爆震/暖机/IAT 侧。

证据等级 B。变量名、正负号和单位按当前软件确认。

## 修改裁决

| 条件 | 状态 | 动作 |
|---|---|---|
| 原厂硬件 Stage1，模型无实测偏差 | `MODEL_NO_EDIT` | 优先检查意图层、权限层和负荷包络 |
| 硬件变化但没有同车模型证据 | `MODEL_REVIEW` | 先收基准 LOG/扭矩参考，不自动改模型 |
| 目标/实际负荷进入原轴外或钳位 | `AXIS_REVIEW` | 查共享轴并建立新域证据 |
| 模型、轴、单位、调用关系任一未知 | `NO_EDIT` | 只输出候选和最小验证步骤 |
| 静态关系看似合理但缺实车闭环 | `LOG_FIRST` | 不宣称已验证或可刷写 |
| 目的只是低报扭矩、绕过 TCU/ESP/limp | `REJECT` | 恢复真实模型，处理实际限制链 |

禁止把论坛中的 `+25%`、`240 load`、某一轴顶值、全表 `FF` 或监控温度标量当作跨文件模板。

## 常见误用说法（默认拒绝）

以下说法在论坛讨论中出现过，均**不作为标定方法**，遇到时直接按对应状态拒绝或降级：

| 误用说法 | 为什么错 | 正确路由 |
|---|---|---|
| "KFMIRL +25%、KFMIOP −10% 就行" | 个别车试验值，反函数≠算术倒数，禁止跨软件版本套用 | `NO_EDIT`，按 LOG 校正 |
| "实际负荷一超 KFMIOP 轴顶，ECU 就立即干预" | 不准确。超末轴点通常沿用末列，但模型失去描述新增负荷的能力，扭矩估算与监控**精度塌陷**——是精度问题，不是硬触发 | `AXIS_REVIEW` |
| "缩小 MAF 就不触发扭矩监控" | 只是让 ECU 看不见真实空气，同时污染实际负荷、喷油、扭矩估算、增压和 TCU/ESP 接口，制造更深的错 | `REJECT`，回真实空气模型 |
| "关掉监控后车更冲，所以改对了" | 更冲只说明平滑与安全干预被移除，不证明扭矩模型正确，也不证明发动机/变速箱/ESP 安全 | `REJECT_MONITOR_DISABLE` |
| "用 MBC 手动加 boost，让 ECU 自己退点火保护" | MBC 让实际增压脱离 N75 闭环，单靠退点火不能可靠保护，也不解决 Lambda、燃油压力、涡轮转速和低转缸压 | 交增压/燃油物理链，非扭矩表 |

## LOG 路由

Bosch ME7 项目优先记录：

- 请求/负荷：`rlsol`、`rl_w`、`rlmax/rlmx`；
- 扭矩链：`mrfa/mifa`、`mibas`、`mimax`、`misol/miszul`；
- 点火路径：`zwgru`、`zwbas`、`zwsol`、`zwout/zwist` 与爆震动态；
- 执行/边界：踏板、节气门、目标/实际增压、WGDC、目标/实测 Lambda、燃油压力、IAT、ECT、故障状态；
- 下游：TCU 扭矩请求、换挡状态、ESP/ASR 干预。

变量名、正负号和单位按当前软件确认。完整采集、时间对齐、测试顺序与停止条件使用
`hp-tuners-log-review` 的 Bosch ME7 扭矩 LOG 专项参考。
