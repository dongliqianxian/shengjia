# 交付防护：真 NOREAD + 漏标体检 + 溯源水印

## 第一条必须先讲清楚的事

**自研工具做不出真正的 NOREAD，别答应用户。**

WinOLS 的再导入禁令，拦截逻辑在 **WinOLS 内部**，判据是「文件里的标记解出来的客户号
== 本机 EVC 狗里的客户号」。报错原文 `marked by **another customer**` 就是证据。
客户号只有 EVC 的狗能签发，所以第三方脚本做不到**「别人开不了、你能开」这种区分**
——它只能做到「谁都开不了」或「谁都能开」。

所以用户要的那三条行为（别的客户号打不开 / 我自己的直接打开 / 导出自动带标），
**只有 WinOLS 自己的导出选项能实现**。本技能的脚本负责它覆盖不到的另一半。

**绝不做**：把别家（如从某个 MOD 里挖出来的）标记复刻到用户文件上。那等于把用户的
文件署上别人家的客户号——文件会被认成是他们出的，而且对方反而能打开用户的文件。

---

## Part 1 · 用 WinOLS 加真 NOREAD

### 硬前置（缺一不可）

1. **正版 WinOLS + EVC 硬件狗。**
2. **狗里写入了客户号（Kundennummer / customer number）。** 最关键、最多人卡住的一条
   ——**标记的内容就是这个号**。没有号，选项要么是灰的，要么打出来的标记没有身份。
   找 EVC 授权经销商确认：我的狗有没有客户号？号是多少？
3. **授权等级要够。** EVC 分 master 和 slave（OLS-Client），再导入禁令属完整授权功能。

### 软前置

4. 在 Options / Settings 里把「导出时应用再导入禁令」设为**默认开**，才有「编辑后
   直接导出自动带标、不需要多余操作」。找不到就按这些关键词搜：
   `Reimport` / `Re-import ban` / `NoREAD` / `Wiedereinlesen` / `Kundenversion`。
5. **每次从干净母版出发。** 不要拿已经打过标的导出文件回炉再改再导——载体已被扰动
   一次，第二次会在扰动上再扰动，误差累积。

### 上线前三项预检（务必让用户做完再交付）

- **不锁自己**：打标 → 在自己的 WinOLS 重新 import，必须能进。进不去 = 客户号没配好。
- **过设备一遍**：打标文件走一次刷写设备（会重算校验和）→ 从 ECU 读回 → 再体检一次，
  确认标记还在。这是整条交付链唯一没验证过的环节。
- **换机验证**：找一台不同客户号的 WinOLS 试导入，确认弹 MSG1872。

### 边界（必须主动告诉用户）

**NOREAD 只拦 WinOLS。** ECM Titanium、BitEdit、TunerPro、HxD 全部照常打开。
只要交付的是裸 bin，「看不了」就做不到。真要严防只有两条路：**只刷车不给文件**，
或用刷写设备自带的 slave / 客户机文件保护。这是天花板，不是配置问题。

## Part 2 · 交付前漏标体检（`check`）

真实运营风险：导出时手一滑没勾上，文件裸奔发出去了，而且**事后无从知道**。

```
python scripts/noread_stamp.py check --ori 原厂.bin --file 待交付.bin
python scripts/noread_stamp.py check --batch 交付目录/ --ori-dir 原厂库/
```

判据复用 `winols-noread-remover/scripts/noread_hidden.py`（车道纯度 100% + 粗糙度比 ≥4×）。
**任何一个「未检出」都不许发货。**

### 它还会报「WinOLS 把数据打偏了多少」——这一栏比有没有标更重要

实测：WinOLS 在丰田 DENSO 89663-58830 上挑中了一张 **uint8 表**
（`0x006852-0x006A72`，545 格，原厂**完美单调，0 处下降**），却按 uint16 只改"低字节"：

| | |
|---|---|
| 中位相对误差 | **12%** |
| 最坏 | `21→31` (+48%)、`31→17` (−45%) |
| 单调性 | 0 处下降 → **89 处下降** |

**WinOLS 的载体挑选在没有定义的平台上是盲猜数据宽度的**，丰田 DENSO 正是这种平台。
所以 `check` 会按 uint8 口径算真实损伤，超过 `--warn-pct`（默认 3%）就告警。
**看到告警，这个项目就别用自动打标**——你没法指定 WinOLS 把水印放哪。

## Part 3 · 溯源水印（`stamp` / `verify` / `strip`）

补 NOREAD 拦不住的那一半：拦不住就改成**抓得到**。每份交付文件隐写客户号 + 订单号，
文件流到同行手里、或从别人 ECU 里读出来，一扫就知道是谁流出去的。

```
# 打标（--ori 强烈建议给：用来定位并避开 WinOLS 的 NOREAD 载体）
python scripts/noread_stamp.py stamp --file 待交付.bin --ori 原厂.bin \
       --key "你的私钥" --customer 1001 --serial 20260822

# 读回（不需要原厂 bin，任何可疑文件都能查）
python scripts/noread_stamp.py verify --file 可疑文件.bin --key "你的私钥"

# 还原（凭 sidecar 精确回滚）
python scripts/noread_stamp.py strip --file 已打标.bin
```

### 设计上刻意不重蹈 WinOLS 覆辙的三点

1. **只翻转最低位**：`v = (v & 0xFE) | bit`。绝不进位，值最多变 1。
2. **载体必须是"高值 uint16 平滑表"**：要求 uint16 值 ≥2048 → 相对误差 ≤ 1/2048 = 0.049%，
   这是**可证明的硬上限**，不是估计值。
3. **用 `mean|低字节−高字节| ≥ 40` 把"字节复制型 uint8 斜坡"整类排除**——正是 WinOLS 踩的坑。
   （实测：被打坏那张 uint8 表的「低==高」比例是 93%；本工具选中的载体是 0%。）

### 为什么 verify 不需要原厂 bin

载体资格**只用高字节车道判定**，而我们从不碰高字节，低字节也先 `& 0xFE` 再参与判定
——所以候选集在打标前后**逐位不变**，verify 能原样重建。payload 自带 magic + CRC16，
滑动扫描试解即可命中。`stamp` 会在写文件前用打标后的数据重跑一次资格判定来自证这一点。

### 抗改动

**3 份副本按【地址】铺开**（不是按槽位序号——合格载体常扎堆在一两张大表里）。
实测：把整个喷油块 8704 字节全部打乱后，剩下 2 份副本仍然读出正确客户号，
并提示"这份文件很可能被别人改过了"。

### 工作流顺序（错了会出事）

```
WinOLS 编辑 → WinOLS 导出（自动带 NOREAD）→ noread_stamp stamp → 交付
                                                  ↑
                        这一步之后【不要】再回 WinOLS 重新导出，
                        否则 WinOLS 重新生成文件，溯源水印被覆盖。
```

- `--key` 是用户的私钥，**只有他自己知道**；换了密钥就读不回旧文件，让他存好。
- sidecar `*.trace.json` 要和文件一起存档，`strip` 靠它精确回滚。
- 校验和：水印写在标定数据里，会让 checksum 失效。用户的刷写设备自动校验就不用管；
  否则打标后要补一次 checksum。

---

## 边界（本技能不做的事）

- 不伪造 WinOLS 的客户号标记，不复刻别家的标记。
- 不去除别人打的 NOREAD（那是 `winols-noread-remover`）。
- 不做标定 / Stage 方案（`stage1-calibration-matrix`），不拆解单表（`ecu-map-analysis`）。
- 不承诺「客户绝对打不开」——裸 bin 交付做不到，见 Part 1 的边界。

## 合规提示

本技能用于保护用户**自己制作**的文件。加标前确认用户对该文件有合法处置权。
