# 参考程序逆向与移植(Reference Tune Porting)

## 0. 本技能解决什么

商业调教里最常见的输入形态:

```
ORI-A + MOD-A  (同车型的原厂文件 + 一份已经在跑的参考程序)
ORI-B          (客户这台车的原厂文件, 软件版本/读取设备/文件大小都可能不同)
        ↓
交付 MOD-B
```

**别人的 MOD 是经验证据, 不是答案。** 它告诉你这个平台上【哪些表真的需要动】——这是从零推导很难覆盖
全的信息;但它同时也带着这一家的捷径和取舍。本技能的立场:**map 选择照抄, 手法逐条重判。**

## 1. 三阶段

### 学 —— 从 ORI-A/MOD-A 逆出配方

```bash
python scripts/diff_cluster.py --ori A_ORI.bin --mod A_MOD.bin \
       --defs defs.csv --json recipe.json
```

整文件 diff → 按间隙聚簇 → 归属到命名 MAP → 逐表解码 → 给出候选算子 + 未归属残留。

- **簇 ≠ 表。** 相邻两份副本会被并进同一个簇, 一个簇里也可能装着两张不同的表。归属必须靠定义,
  不能靠簇边界。
- **候选算子只有四种**: `scale` / `offset_raw` / `flatten` / `table`。其中 **`flatten` 优先于 `scale`
  判定**——"原来有形状、改完变常数"是安全相关信号(监控/保护被拍平), 绝不能被当成普通缩放放过去。
- **倍率判据用最小二乘拟合 + 残差 ≤1**, 不用 min/max 比值。原始值小的时候取整误差会把比值散开
  (110×1.25=137.5→138, 比值 1.2545; 而 100×1.25=125, 比值 1.25), 任何与量级相关的阈值都不可靠。
- **未归属残留必须逐条处理, 不得忽略。** 它们要么是定义文件没覆盖的表, 要么是漏定义的副本。

定义来源(本技能不产定义): `damos-a2l-parser` / `winols-ols-parser` / `winols-screenshot-analyzer`
抄工具定义树 / `bin-to-a2l` 穷举自描述容器。

### 证 —— 逐表证明配方能落到 ORI-B 上

```bash
python scripts/port_verify.py --src A_ORI.bin --dst B_ORI.bin \
       --defs defs.csv --region 0x180000-0x1E0000 --json proof.json
```

**这一步是本技能存在的最主要理由。** 拿 A 的地址去改 B, 如果某张表因软件版本挪了位:
diff 看不出来 / 解码看不出来 / 写盘不报错 / checksum 也能算对——**装车才知道**。
这是静默灾难: 不做这一步的时候, 一切看起来都是对的。所以默认【有罪推定】。

| 判定 | 含义 | 可用性 |
|---|---|---|
| `PROVEN_IDENTICAL` | 同址字节完全相同 | 任何算子都安全 |
| `PROVEN_BY_DESC` | 同址自描述符(维度+轴)一致, 仅标定值不同 | **相对算子可照搬; 绝对算子(flatten/写定值)必须按 B 的原值重判** |
| `PROVEN_BY_CONTEXT` | 数据块前后文两文件一致(给无描述符的表和 1×1 标量) | 同上 |
| `MOVED` | 原数据块在 B 中唯一出现于别处 | 改地址后可用 |
| `AMBIGUOUS` / `UNPROVEN` | 证不出来 | **必须剔除, 并在交付说明里写明这张表没做** |

退出码 0/1 可直接卡流水线。**"大概是这个地址"不是一个允许出现的状态。**

#### 有 A2L 时也一样要证 —— 地址偏移不是常数

用别的数据集的 A2L 给目标 bin 定位时,**不要用一个锚点算出 delta 再套到别处**。
实测 Bosch P1793(MG1CS002):同工程 MY19B00 的 A2L 对 MY19DP6 的 bin,
偏移在 **−0x70 到 +0x1363C 之间随地址单调漂移** —— 标定区是顺序排布的,
前面多一张表,后面全部平移。套 delta 会静默指到隔壁那张表。

正确做法是**结构匹配**(不是地址匹配):

1. 从 bin 的自描述头解出**维度 + 轴原始值**;
2. 拿候选 CHARACTERISTIC 的 COMPU_METHOD 解码,只有**两个轴的物理量、单位、量程
   全部落在 AXIS_DESCR 声明区间内**才算命中(轴单调 + 落在 [lo,hi] 是硬判据);
3. 候选不唯一时,用**同族对象间距**交叉验证 —— 记录总长在两边必须一致。
   本次用 `0x1A`(6 点曲线)/`0x1A2`(12×15 图)/`0x6E`(8×5 图)/`0xD2`(12×7 图)
   四个间距独立确认;再不够就用连续若干对象的**维度序列指纹**收敛。

> `port_verify.py` 的 `PROVEN_BY_DESC` 判的是「同址描述符一致」;
> 跨数据集时**同址本身就不成立**,必须先做上面的结构匹配把地址找出来,
> 才轮到判 verdict。

### 出 —— 应用并回读自检

字节写入交 `bosch-conti-bin-engine`(或对应 bin 引擎)。本阶段的纪律:

1. 只写 `verdict=PROVEN_*` 的条目, 逐条打印 ORI→MOD。
2. 写完**重新读回输出文件**独立复核一遍, 不信任内存里的中间态。
3. 断言**标定区之外零改动**、程序区与 ECU 身份串未动。
4. 产出 changelog 随 bin 一起交付(模板见 `stage1-calibration-matrix/assets/changelog-template.md`),
   必须含【故意没改的表及原因】一节——这是审计型交付与普通改装文件的区别。
5. **checksum 一律不算**, 交 `checksum-crc-engine` / WinOLS 插件 / 刷写工具, 并明说文件当前不可刷。

## 2. 审计判据(反方向的 stage1)

逐条给参考 MOD 的每个改动打 **keep / fix / drop**。判定规则**不在本技能造**, 全部引自
`stage1-calibration-matrix` 模块 6 与 doctrine。本技能只固化"怎么问":

| 问题 | 处理 |
|---|---|
| 主控表被压低而硬件没变? | 骗扭矩 → 见 `torque-model-builder` §6.5 骗扭矩判据, 默认 **drop**, 改走"整条路径一致抬" |
| 安全/监控表被拍平成常数? | **drop**。要抬就按比例保形抬, 保住监控功能 |
| 空气模型(节气门流量/MAF/VE)被改? | 除非是在修真实建模误差, 否则 **drop**(doctrine 原则#3, 误差 ≤3%) |
| 排放诊断窗口被关闭? | **drop**。OBD readiness 不就绪 = 年检过不了 |
| 爆震阈值被调钝? | **drop**。加气加点火的同时把探测调钝, 方向相反 |
| 燃油表出现比原厂更稀的格? | **fix** 成"只加浓不变稀" |
| 保护类修正(IAT/水温)被拍平? | **fix** 成保形抬升, 梯度必须留住 |
| 副本只改了一部分? | **fix**。用 MOD 的改动位置当种子跑 `parallel-map-finder` 验证齐全性 |

## 2.5 写入前 preflight 门禁(可执行,不是清单)

**在写任何字节之前**,对整批目标表逐表算跨度并做两项检查。这是 doctrine §6.4 写入门禁的**可执行化**。

```
span_bytes = rows × cols × size_bytes          # size_bytes 按实际 dtype,不写死 2
lo = addr ; hi = addr + span_bytes - 1
```

| 检查 | 判据 | 失败处置 |
|---|---|---|
| **越界** | `hi < len(bin)` | 该表 **SKIP**,报「维度或基址错」 |
| **区间重叠** | 任意两表 `[lo,hi]` 不得相交 | **全批中止**,先解决重叠再写 |

> **为什么重叠是全批中止而不是跳过**:重叠意味着至少有一张表的**维度或地址是错的**。
> 此时"跳过冲突的那张、写其余的"会**把一张错表的错误当成已验证**继续用下去。
> 典型后果:改燃油表**溢进相邻点火表**,而 diff 看起来完全正常。

轴数组与 Z 块要**分别**登记跨度 —— 轴常紧邻 Z 块,是重叠的高发区。

## 2.6 移植分类轴(与「主控/限制/监控/修正」正交,可并存)

配方里每一条改动,除了功能属性,还要标一个**可移植性**分类:

| 分类 | 含义 | 处置 |
|---|---|---|
| **DIRECT_COPY** | 目标文件同地址同维度同 dtype,轴也一致 | 直接搬,回读自检即可 |
| **RESAMPLE** | 功能相同但**轴断点不同** | 按物理量插值重采样,**不得**按格号硬搬 |
| **CONVERT** | dtype / factor / offset 不同 | 先转工程值再转回目标 raw,交 `winols-scaling-converter` |
| **MANUAL_REVIEW** | 目标文件里对应表**没找到**或维度对不上 | 停,交 `parallel-map-finder` / `ecu-map-analysis` |
| **MAX_ONLY** | 限制/保护类表,目标文件自己的值在某些格**已高于**参考 MOD | 逐格 `max(目标原值, 参考MOD)`,只抬不降 |
| **SKIP** | 源改动本身判为不合理(见 §2 审计判据),或 preflight 越界 | 不移植,在报告里写明原因 |

**纪律**:`RESAMPLE` 与 `CONVERT` 必须逐表给出**证明**(§1「证」阶段的回读自检),
不得因为"看起来对得上"就降级成 `DIRECT_COPY`。

### 2.6.1 用相对算子之前的强制闸门:孪生检查

**逐格比(`ratio` = MOD-A ÷ ORI-A)只有在「源文件的 ORI 就是目标想要的起点」时才安全。**
源文件同族里只要有两份原厂数据不一样,逐格比就会把**那个差异**当成调教意图搬过去。

```
用 ratio / 写定值之前必答:
  这张表在【源文件】里有没有同族孪生或副本?      ── 有 ──▶ 它们的【原厂值】是否相同?
                                                              │
                                                        不同 ──▶ 禁用 ratio,改 MAX_ONLY 或按物理意图重定算子
```

**两个实证(同一类错误,在同一个项目上栽了两次)**:

| 表 | 源文件情况 | 目标文件情况 | 照搬的后果 |
|---|---|---|---|
| `CByVlv_ratPCmprHysLim_M` 副本2/5(喘振迟滞) | A8 三份副本填成同一张 | 途锐三份各不相同,高流量段更高(3.800/3.900) | 参考 MOD 只到 3.328/3.432 → **把目标原厂值压低**,WOT 大流量提前泄压 |
| 压比上限孪生对 `0xE9F18`/`0xEA15C` | A8 两份原厂就不同 | 途锐两份**字节完全相同** | 逐格比里带着 −0.6%…−4.4% 的中段下调 → 3500–4000 rpm 压比上限**低于目标原厂**(2.555→2.443) |

第二例还暴露了另一件事:**参考程序自己漏改了孪生的另一半**(`0xE9F18` 原样未动)。
所以孪生检查是双向的 —— 既防止把源的差异搬过来,也补上源漏掉的副本。

**配套硬断言**(写完必跑):限制/保护类表**没有一格低于目标原厂**。
副本齐全性交 `parallel-map-finder`;找同族用**共享轴的字节签名**扫描最省事
(本次用 8 点转速轴签名在 0x10000 范围内扫出「恰好两处」,确认是一对而不是三张)。

> *依据 doctrine §6.4 写入门禁的可执行化；分类轴源自 KingAiCodeForge/tunerpro-xdf-bin-cli-map-editor 的移植实践。*

## 3. 与其它技能划界(不重叠)

| 技能 | 输入 | 与本技能的区别 |
|---|---|---|
| `stage1-calibration-matrix` | 无 MOD | 从零【正向】出方案矩阵。本技能是【有 MOD】的逆向 + 移植, 判定规则反过来引它 |
| `ecu-calib-finder` | 一堆文件 | 在**文件库里找**兼容文件 + 可刷性。本技能是**两个已在手的文件之间**做逐表证明 |
| `parallel-map-finder` | 同 bin + 种子 | 找副本。本技能**必须调它**验证参考 MOD 有没有漏改副本 |
| `bin-to-a2l` | 裸 bin | 穷举自描述容器全表清单。本技能的描述符探针只做**局部校验**, 穷举交它 |
| `ecu-map-analysis` | 单张表 | 单表功能判定。本技能出的是整份配方 |
| `damos-a2l-parser` / `winols-ols-parser` | 定义文件 | 产定义。本技能**消费**定义 |

## 4. 脚本

```bash
python scripts/diff_cluster.py --selftest      # 20 项
python scripts/port_verify.py  --selftest      # 12 项
```

`assets/defs_mevd1729_b20_8709.csv` 是一份实测可用的定义(Bosch MEVD17.2.9 / BMW N20 F18,
ECM Titanium 驱动 B20_8709), 几何全部经自描述符+副本交叉验证证实, 可直接当格式样例。

定义 CSV: `name,addr,rows,cols,dtype,copies,unit,factor,offset,stride`
`stride` 留空则自动推导——优先用数据块后的自描述符, 多副本时用**下一份副本的描述符是否落位**做
交叉验证(这是唯一能可靠区分 u16 轴与 u8 轴的判据), 推不出来按 packed 处理。

## 5. 诚实边界

- 本技能不产定义、不判单表功能、不写 checksum、不出各厂命名。
- **参考 MOD 的 map 选择是证据, 手法不是。** 商业文件里的捷径(压模型/拍监控/关诊断)能跑, 代价
  具体且可量化, 必须逐条摆出来让人做选择, 而不是照抄或一律否定。
- 换算系数在没有 A2L 时是**反推**的: 倍率与 raw 差值永远是事实, 物理单位是推断, 报告里必须分开写。
- `port_verify` 的闸门是为 **ORI vs ORI** 设计的。拿一份已调教文件当 B, 相邻表也被改过时会
  合理地判出 UNPROVEN——那不是误报, 是输入不对。

## 6. 输出纪律

- 先出【改了什么】(事实: 地址/维度/倍率/raw 差值), 再出【合不合理】(判定), 两者不混写。
- 每条改动必须标 keep / fix / drop 与理由, 不允许"参考文件这么做的"作为理由。
- 移植报告必须包含未通过闸门的表清单与处置(剔除还是改地址), 不得静默跳过。
- 交付必须同时给出: bin + changelog + 未做的表及原因 + checksum 未算的明示。
