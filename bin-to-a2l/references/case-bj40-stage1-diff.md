## 三条方法论收获

### ① 只看峰值会漏判

喷油器通电时间表 **峰值 +0.0%**,肉眼比对 max 会判成"没动"——实际 **209 格被改了 +2.9%~+8.0%**。
→ `stage_diff.py` 必须报**逐格改动数**,不能只报 max。这条是本案例直接催生的。

### ② uniformity 统计量能读出"怎么做的"

- **uniform**(全表同一个比例):标量、曲线、限制器 —— ×1.2000 / ×1.1500 / ×0.9800 这种整数比例
- **shaped**(比例随区域变):主控 map —— 1.060–1.100 表示低负荷区少加、高负荷区吃满

一份全是 uniform 的改件 = 按百分比缩放的批量文件;有 shaped 的 = 有人分区做过。

### ③ 差分能找出定义集的漏洞

按 ECM 的 `[N]` 分组 + 步长走描述符,**仍漏掉 16 张被改动的增压表**。
只有拿全量结构清单(2022 条)去归属,才做到 100% 覆盖。
→ `stage_diff.py` 应同时吃 `--maps`(覆盖)和 `--spec`(命名)。

## 对这份 Stage1 的工程评价

**燃油 +27.6%,增压只有 +10%。** 按第一性原理算 λ(VE 0.95 / IAT 50°C / AFR 14.5):

| 转速 | λ 原厂 | λ Stage1 |
|---|---|---|
| 1200 | 1.058 | **0.909** |
| 1600 | 1.276 | **1.021** |
| 2600(峰值扭矩) | 1.366 | **1.177** |
| 3800 | 1.573 | 1.391 |

而且**烟度 λ 下限被降了 2%**,削弱了保护。**涡轮压比只到 2.98,空气侧还有余量却没给。**

低转 λ 低于地板在原厂文件里也存在(上限≠实际喷油量,低转由烟度限制器管),
所以实际不会真跑到 0.909 —— 但结论成立:**燃油上限被抬到远超增压能支撑的程度,
烟度限制器在大半个转速区间成为实际限制,车拿不到 +27.6%,却会比原厂明显更冒烟。**

> 这不是"商用文件一定不好",而是**这一份的空气/燃油配比与"空气优先"原则相悖**。
> 同样的目标,先把增压给到 +15~18%(压比仍在余量内)、燃油压到 +12~15%,λ 可以守在 1.30 以上。

**误差带**:VE/IAT/η 均为假设,绝对值 ±5%;**趋势(λ 掉 14%)可靠**。
