# bin → A2L(自描述标定容器的全链路)

## 0. 先分流:本技能只管一种情况

| 你手上有 | 用哪个 | 产出 |
|---|---|---|
| 裸 bin,平台未知 | **本技能第①步探针** | 判定自描述与否 |
| 裸 bin,**探针判定自描述** | **本技能全链路** | 全表清单 + A2L |
| 裸 bin,**探针判定非自描述** | → `blind-map-finder` | 排序候选地址 |
| 已有 A2L / DAMOS | → `damos-a2l-parser` | 读定义 |
| 已有 .ols / .kp | → `winols-ols-parser` | 抠定义树 |
| DENSO/RH850,想从**代码**扫全表 | → `denso-rh850-map-inventory` | 代码证实的表清单 |
| 已知一张表,找它的副本 | → `parallel-map-finder` | 平行/镜像副本 |
| 已知一个数值(限速/怠速) | → `speed-limiter-removal` 的 `value_locate.py` | 值驱动候选 |

**本技能不重复造这些轮子**,只补一段现有技能都没有的链路:**容器 ABI 发现 → 穷举 → 物理验证 → 写 A2L**。
现有技能里没有任何一个【生成】A2L(`damos-a2l-parser` 只读不写)。

## 1. 什么是"自描述容器"

有些 ECU 把每张表存成自带元数据的描述符:

```
[u16 rows][u16 cols][X轴: rows×u16][Y轴: cols×u16][数据: rows*cols×u16]
```

只要平台是这样,**整份标定的清单就是机械可得的**——不需要 A2L,不需要反汇编。

**已实测成立的平台**(每一个都用控制组坐实,不是推测):

| 平台 | 核 | 文件 | 探针命中 / 错字节序比 | 控制组 |
|---|---|---|---|---|
| **Bosch MD1CS089**(ISUZU 1.9) | AURIX TC299TP | 8 MB 全 dump | 2189 / **78x** | 9/9 已知表 |
| **Bosch MD1CS089**(BAIC BJ40 2.0) | AURIX TC299TP | 8 MB 全 dump | 2022 / **78x** | **20/20** ECM 地址 |
| **Bosch EDC17C63**(JMC 2.x) | TriCore | 1.5 MB 标定区读取 | 471 / **118x** | **18/18** ECM 地址 |
| **Bosch EDC17C83**(ISUZU 1.9) | TriCore | 2 MB | 2009 / **143x** | 差分覆盖 **96.4%** |
| **Bosch EDC17CP55**(Land Rover 3.0) | TriCore | 2 MB | 2279 / **190x** | 差分覆盖 79.1% |

跨度已覆盖:**直四 1.9/2.0/2.4L ↔ 直六/V6 3.0L MHEV**、日系/中系/英系四个 OEM、
**1.5–8 MB**、**mg/stroke ↔ mm³/stroke** 两种喷油单位。

> **这是 Bosch 柴油 ECU 的跨代通用约定**,不是某一代的特例:TriCore 时代的 EDC17(C63/C83/CP55)
> 和 AURIX 时代的 MD1 用的是**同一个容器布局**。遇到 Bosch 柴油 ECU,先假设自描述,用第①步验证。

仍然不是所有 ECU 都这样(裸数据块 + 独立轴引用的平台存在),第①步会判出来并交回 `blind-map-finder`。

## 2. 四步链路

```
① abi_probe.py       多容器布局 × 双字节序 × 双数据宽度,按"自洽块数"打分
                     ★ 判据: 对【错字节序对照组】≥8 倍 且 命中 ≥200 → 自描述
                     ★ 判不出 → 交回 blind-map-finder,不硬撑
                     ★ 同时输出【代码存在性】: 这个文件里到底有没有 ASW
② cal_inventory.py   穷举全表 + 轴种类识别 + 粗糙度分级(BASE/CORRECTION/FLAT)
③ physics_check.py   ★ 全局闭环闸门: 反算功率扭矩 vs 厂标,不通过不准往下走
④ emit_a2l.py        分组 A2L + 回读自检(维度对不上就报错,不产出"看起来对"的错定义)

⑤ stage_diff.py      【有改装件时优先做这一步】ORI vs MOD 差分

⑥ verify_edit.py     ★★ 输出任何改好的 bin 之前【强制】跑,不过不准交付
```

## 2.0 第⑥步:交付前的控制逻辑闸门(强制)

**改完 map 不等于改对了。** 每张表单看都正确,运行时的限制链仍然可以把它毁掉,
而且**文件上完全看不出来**。

> **实测(ISUZU 1.9 RZ4E / MD1CS089)**:增压目标抬到 3555 hPa,增压硬顶 `0x4D7992`
> 留在 3000 hPa 没动。ECU 运行时取 `min(目标, 硬顶)`,于是**增压只涨了 ×1.03,
> 而燃油涨了 ×1.20 —— λ 比塌到 0.86**,"不增加 DPF 再生"这个核心设计目标彻底失效。
> 每张表检查都通过,是用户看 ECM 截图发现的。

```bash
python scripts/verify_edit.py --ori ORI.bin --mod OUT.bin \
       --maps inv.json --spec spec.json [--allow 0x4D7992]
```

三项检查,**全部硬失败(exit 2),不是警告**——警告会被漏看:

| # | 检查 | 抓什么 |
|---|---|---|
| 1 | **裁切限制器** | 抬高的值,同组内还有未抬的平表压在下面 |
| 2 | **漏改平行副本** | 未改的表是已改表的近似复制 → 模式间行为不一致 |
| 3 | **拍平 / 饱和** | 成形表被改成常数,或被拉到 `0xFFFF` |

### 为什么第①项必须给 `--spec`

用**数值量级**猜"哪张平表是哪张目标的限制器",在真实 8 MB 文件上不可用。实测三版:

| 判据 | 结果 |
|---|---|
| 同十倍频程 | **2000+ 误报** |
| 同十倍频程 + 256 KB 地址窗 | **208 误报,且正确的文件也 FAIL** → 闸门无信号 |
| **限定在人工分好的功能组内** | **精确命中,0 误报** ✅ |

根因:判断"同一物理量"需要单位和控制流关系,**这两样都不在文件里**(见第 6 节)。
数值猜不出来,**必须用人工赋予的分组知识**。所以没有 `--spec` 时闸门**报失败**,
不静默跳过。

### 配套纪律

- 余量算 **行最大值**,不是"某个代表点":同一转速行里别的负荷点通常更高,先顶到限制器。
- **抬限制器本身时**,必须单独说明**保护阈值放宽了百分之几**,交用户决策,不得默默改。
- 造测试用例时警惕**假阴性**:实测中第一版"故意造错"的文件闸门竟然 PASS——
  因为构建脚本自己的限制把目标也压下去了,根本没复现原始故障。**假阴性比误报更危险。**

## 2.1 第⑤步:有 ORI+MOD 就先做差分

**一份改好的文件是一张标注好的答案卷。** 做这个文件的人已经替你决定了:哪些表定义功率、
哪些平行副本必须一起动、哪些表绝对不能碰。从差分上读出来只要几秒;从第一性原理推要几小时,
而且永远没这么确定。

它给四样别处拿不到的东西:

1. **哪些表定义了功率** —— 按改动幅度排序
2. **改法是均匀缩放还是分区塑形** —— uniformity 统计量(实测能区分"整表 ×1.20"和"1.06~1.10 分区")
3. **哪些表被【刻意不动】** —— 负向信号,常常是更有价值的一半(喷油器传递函数、机械极限标量)
4. **你的定义集漏了什么** —— 有改动但没有任何已知表覆盖的字节

**实测(BJ40 MD1CS089,17,777 字节改动):未归属字节 0/17777 = 100% 覆盖**,
且找出了 16 张我手工按 ECM 分组走出来时**漏掉**的增压表。

> **实测教训:只比较峰值会漏判。** 喷油器通电时间表峰值 +0.0%,看起来"没动",
> 但实际 209 格被改了 +2.9%~+8.0%。**必须看逐格改动数,不能只看 max。**

### 2.1.1 覆盖率 = 没有厂商驱动时的【替代控制组】

第①步的探针只证明"存在大量自洽块",不证明"这些块就是真的表"。有 ECM/WinOLS 定义时用已知地址
做控制组;**没有定义时,用 ORI/MOD 差分覆盖率替代**:

> ABI 判错的话,调教师改的字节不会整齐落进描述符内。**覆盖率高 = ABI 正确。**

实测:EDC17C83 **96.4%**、EDC17CP55 79.1%、BJ40(配 spec)**100%**。

**覆盖率天花板取决于你喂了什么:**

| 输入 | 能覆盖 | 盲区 |
|---|---|---|
| 只给 `--maps` | 维度 4–48 的表 | **1×1 标量全部看不见** |
| `--maps` + `--spec` | 表 + spec 里列出的标量 | spec 没写的 |

EDC17CP55 那 21% 未归属主要就是标量。**要接近 100% 必须同时给 `--spec`。**

### 2.1.2 flatten 检测是这一步最有价值的单项

`uniform ×0.0000`(清零)与饱和到 `0xFFFF` 这两种形态,**必须优先于百分比排序看**。
纯按百分比排,"−100%" 很容易被当成一个普通的负向缩放略过。

**实测:5 份商业改装件里 2 份有此类改动**——

- EDC17C83:**6 张清零 + 2 张拉满 0xFFFF**
- EDC17CP55:1 张清零(16×25,368 格,14500 → 0)

判定规则见 `reference-tune-porting` 的审计表:**"原本有形状 → 改成常数" 一律 drop**,
不管你能不能叫出它的名字。本技能只负责**把它检出来并标红**,功能定性交
`ghidra-tricore-disasm`(找谁读这个地址)或 A2L。

### 2.1.3 λ 比 —— 判改装件质量的客观判据

差分的按域汇总能直接算出:

```
λ比 = 增压倍率 ÷ 燃油倍率
```

**这个量与排量、缸数、VE、进气温度全部无关**——都在分子分母里约掉了。所以
**连车型存疑、排量不确定的文件也能判**(实测 JMC 那份文件名同时写 2.4T 和 2.9L,照样能判)。

| λ比 | 含义 |
|---|---|
| ≥ 1.00 | 空气跟得上燃油,碳烟不高于原厂 |
| 0.95–1.00 | 轻微偏浓,可接受 |
| < 0.95 | **油跑在气前面**:碳烟上升、DPF 再生变频繁、烟度限制器会反过来扣油 |

碳烟量级估算:`soot ∝ (1/λ)^5`(烟度限制附近的常见陡度,数量级指标不是标定模型)。
λ 比 0.877 → 碳烟约 1.5x → **DPF 再生间隔缩短约 35%**。

**五份商业改装件实测,四份 < 0.95:**

| 改装件 | ECU | 燃油× | 空气× | λ比 |
|---|---|---|---|---|
| Land Rover Stage1 | EDC17CP55 | 1.10–1.13 | 1.06 | 0.93–0.96 |
| JMC Stage1 | EDC17C63 | 1.25 | 1.08 | 0.877 |
| BJ40 Stage1 | MD1CS089 | 1.28 | 1.10 | ~0.86 |
| ISUZU Stage1 | EDC17C83 | 1.22 | 1.04 | **0.851** |
| JMC Stage1.2(本技能修正版) | EDC17C63 | 1.10 | 1.10 | **1.000** |

> 按百分比批量缩放燃油比调增压容易,所以商业件普遍"油跑在气前面"——
> 这是 doctrine "空气优先" 原则在真实文件上的统计验证。
> **修正手法**:把燃油降到与空气同倍率,或把空气抬到与燃油同倍率(压比有余量时优先后者)。

## 3. 三条必须硬守的纪律

### ① 对照组是强制的

任何"我找到了 X"的结论,都要有一个**已知为真的对照组**跑同一条判据。

实测教训(MD1CS089):Ghidra xref 对所有 map 返回 0,包括**已经证实为真**的轨压/增压/驾驶员需求。
正是这个对照组证明了"0 是寻址方式的性质,不是地址错了",避免了把一个巧合命中当成突破口。
后续两个假设(指针表、`movh.a` 重建)也都是被对照组 0/8 证伪的。

`abi_probe.py` 内置的对照组是**错字节序**;`emit_a2l.py` 内置的是**维度断言**。

### ② 物理闭环闸门不通过,不准产出 A2L

`physics_check.py` 反算功率/扭矩对不上厂标,说明 ABI、字节序、数据宽度或缩放判错了,
**后面全是错的**。这是唯一能一次性验证整个解码链的手段。

**两个必须显式处理的输入**(EDC17C63 实测踩到):

- **喷油量单位是质量还是体积**:MD1 用 **mg/Stk**(质量),EDC17 用 **mm³/Stk**(体积)。
  差一个柴油密度 0.832,不折算会系统性高估 20%。用 `--units volume`。
- **扭矩可能没有**:中国铭牌常只标功率(实测 JX4D24A5L 铭牌只有 103 kW,无 Nm)。
  `--nm` 可省略,但**只用功率打分判别力弱得多**——实测 EDC17C63 上前几名全是轨压图凑巧闭合。
  **闸门此时只能验证"解码没有量级错误",不能用来认表。**

**闸门的分辨率有限**:实测 EDC17C63,η=0.385 → 93.4 kW(偏向 92 kW),η=0.42 → 101.9 kW
(偏向 103 kW)。**两个候选额定值只差 12%,落在 η 假设的不确定带内,闸门分不出。**
闸门能抓的是 10 倍级的缩放错误,不是 10% 级的变体差异。

### ③ 粗糙度分级要保留 —— 但要读对它的含义

二阶差分均值 ÷ 全量程,沿两个轴各算一次:

| 类别 | 实测区间(MD1CS089) | 含义 |
|---|---|---|
| **平滑** | 0.6% – 2.8% | 设计出来的连续控制曲面(轨压/增压/燃油/扭矩) |
| **毛糙** | 6.4% – 11.9% | **逐格人工优化过**的表 |

两者**无重叠**,判据**不依赖平台**。

> ⚠️ **这个判据说的是"怎么做出来的",不是"是什么表"。**
>
> **实测教训**:我曾据此判定六张 `−5.1~+12.8 / −21.0~+12.0 / −3.8~+3.7 degBTDC` 的表
> "是修正类不是基础表"。**错了**——厂商工具明确命名它们为 `Main Injection Base Map 1 #1..#6`,
> 是**主喷射正时基础表**。
>
> 原因:**主喷正时本身就是逐格针对排放和噪声优化出来的**,天生毛糙。
> "平滑=基础表"这个直觉只对**物理上连续的量**(压力、流量、扭矩)成立,
> 对**排放标定主导的量**(喷射正时、EGR、后处理)不成立。

**正确用法**:

| 结论 | 成立? |
|---|---|
| 毛糙 ⇒ **整体缩放会抹掉不可复现的台架工作**,别乘系数 | ✅ 永远成立 |
| 平滑 ⇒ 是连续控制曲面,按比例改讲得通 | ✅ 成立 |
| 毛糙 ⇒ **它是修正表不是基础表** | ❌ **不成立**,别这么推 |

### ④ 反向判据:限制器低于原厂输出 ⇒ 它不在主路径上

第⑥步闸门找的是"**高于**新峰值的限制器会裁切"。反过来同样有用:

> **一个限制器的值如果低于原厂已经做到的输出,它就不可能是主路径上的无条件限制器
> ——否则原厂自己都做不到标称值。**

**实测两例**:

| 文件 | 限制器 | 值 | 原厂输出 | 结论 |
|---|---|---|---|---|
| ISUZU 130 kW | `0x53DFE6` | 393.1 Nm | **410 Nm** | 不是无条件主限制器 |
| ISUZU 120 kW | `0x5ABA3C/8E/E0` ×3 | 全部 **300.0 Nm** | **360 Nm** | 同上,**正确地没去动它们** |

这类表是**条件性限制器**(特定模式/挡位/温度)。抬它们等于放宽一个**触发条件未知**的保护
——**没有依据的改动,不做**。

对照:增压硬顶 3000 hPa 是**高于**原厂有效增压的(它就是有效增压),所以必须抬。
**两种情况方向相反,判据就是"和原厂实际输出比大小"。**

## 4. 脚本

```bash
# ① 容器 ABI 探针(先跑这个,决定要不要继续)
python scripts/abi_probe.py --bin ECU.bin --json abi.json
python scripts/abi_probe.py --selftest

# ② 穷举清单
python scripts/cal_inventory.py --bin ECU.bin --abi abi.json --json inv.json --named-only

# ③ 物理闭环闸门(同时自动缩小燃油上限表的候选范围)
python scripts/physics_check.py --bin ECU.bin --maps inv.json \
       --disp 1898 --cyl 4 --kw 130 --nm 410 --fuel diesel
# 单点空气侧核算: 给 mg/stroke、增压 hPa、进气温度
python scripts/physics_check.py --disp 1898 --cyl 4 --lambda-check 82 3350 50

# ④ 产出 A2L(spec 由人判定功能后编写,见 references/spec_example.json)
python scripts/emit_a2l.py --bin ECU.bin --spec spec.json --out ECU.a2l --also-file-offset

# ⑤ 有改装件就先跑这个 —— 同时给 --maps(全覆盖)和 --spec(带命名)
python scripts/stage_diff.py --ori ORI.bin --mod TUNED.MOD \
       --spec spec.json --maps inv.json --base 0x80000000 --show-unchanged
```

五个脚本都支持 `--selftest`(含合成数据 + 负向对照)。

## 5. 第③步之后仍然要人判断

物理闸门给的是**短名单不是答案**。实测 MD1CS089:真正的燃油上限表排名**第 2**,
第 1 名是数值上凑巧闭合的假阳性。

功能命名靠这几条,按可靠度排序:
1. **独特物理量纲**——增压只能是 1013–3090 hPa 绝对压力;轨压 200–1500 bar;排温 750–1040 °C
2. **轴组合**——踏板×转速 = 驾驶员需求;转速×喷油量 = 主控面
3. **形态自证**——"EGT 随 λ 升而降"这类物理必然
4. **粗糙度**——判"是否逐格优化过"(即能不能整体缩放)。**不能**用它判基础表 vs 修正表,见纪律③
5. **厂商工具/已有定义**——线索不是证据,实测 ECM Titanium 在 MD1CS089 上把单位标错(mg/stroke 标成 Nm)、
   把烟度表地址和维度都标错

**无量纲的表判不了**,别硬命名。命名时宁可用中性名(`Correction_A`)也不要用会误导的确定名。

单表功能拆解交 `ecu-map-analysis`;换算细节交 `winols-scaling-converter`。

## 6. 做不到的事(写死,别承诺)

- **反汇编找 map**:自描述平台上无效。实测 MD1CS089,785,850 条指令中仅 3 条引用标定区,
  xref / 指针表 / `movh.a`+`lea` 重建三条路全部 0/8。Ghidra 在这类平台只能给你
  **基址、镜像分区、和一个可靠的否定结论**。工具链搭建仍交 `ghidra-ida-setup`。

- **在【只有标定区】的文件上做任何代码级分析**。这是比上一条更硬的边界:
  **代码根本不在文件里**,不是"难",是标的物不存在。

  > `abi_probe.py` 第①步已自动判定并输出。判据是每 64 KB 熵值,阈值 **6.2**,
  > 用一个已证实的镜像标定过(Ghidra 证实代码区 9,633 个函数):
  >
  > | population | mean | max |
  > |---|---|---|
  > | 已证实代码区 | 6.41 | 7.06 |
  > | 已证实标定区 | 3.47 | 4.81 |
  >
  > **实测:EDC17C83 (mean 3.47 / max 5.14) 与 EDC17CP55 (mean 3.94 / max 5.33)
  > 都精确落在标定区那一族 —— 两份 bench 读取都不含 ASW。**
  > 反查:MD1CS089 全 dump 判出 41 个代码块 `0x020000-0x3CFFFF`,与 Ghidra 独立结论吻合。

  **后果**:`flatten` 检测能把一张可疑表标红,但**要给它定功能,必须有全 dump**。
  台架只读标定分区的文件回答不了"这张表是干什么的"。这时候唯一的出路是 **A2L/DAMOS**。
- **判断多份平行表哪份在什么条件下生效**:静态分析给不了,要 LOG。
- **checksum / 签名**:交 `checksum-crc-engine`;MD1/MG1 的 RSA 引导签名本地伪造不了。
- **写 .kp / .ols / DAMOS**:私有二进制格式,写不了。A2L 是公开标准,这也是本技能选它的原因。

## 7. 让结果更准,该向用户要什么(按实测杠杆排序)

1. **额定功率 kW / 额定扭矩 Nm / 排量 / 缸数 / 燃料** —— 第③步的输入,同时锁死数据宽度歧义。
   成本几乎为零,杠杆最大。**没有它,第③步跑不了**。
2. **变速箱型号 / 输入扭矩容量** —— 决定方案上限。
3. **任何已有定义**(厂商工具截图 / .ols / XDF / 半份 A2L)—— 哪怕 5 个地址就能锁死第①步的两个歧义。
4. **同平台第二个 bin** —— **单项技术杠杆最高**,但**必须同一个 SW 版本**:
   - ✅ **ORI vs 其改装件**(同 SW):一次 diff 直接指出哪些表定义功率 → 第⑤步
   - ❌ **跨 SW 版本的变体对比无效**。实测两份 ISUZU MD1CS089:
     `10SW056329`(120kW)vs `10SW100085`(130kW),已知 map 地址 **0/12** 对得上,
     整文件 **51.2%** 字节不同 —— 是一次 Stage1(0.052%)的 **985 倍**,全是重定位噪声。
   - **先比 SW 号再决定能不能 diff**;不同版本就各自独立走全链路,只比**物理量**
     (mg/stk、hPa、Nm),不能比地址。
5. **数据流 LOG** —— 唯一能解开"多份平行表哪份生效""正时表是主喷还是预喷"的东西,
   并把 VE / IAT / eta 这些假设换成实测。

## 9. 输出纪律

- 地址永远标明是**文件偏移**还是**加了 base 的内存地址**。
- 第①步的两个残留歧义(行列序、数据宽度)**必须显式说明如何解决**,不能默默选一个。
- 功能命名带置信度:✅已证实 / 🔷强推断 / ❓候选。A2L 文件本身可以干净不带标注,
  但**给用户的说明里必须分级**。
- 第③步的绝对数字带 ±5% 误差带(eta 假设);**比例可靠,绝对值不可靠**。
