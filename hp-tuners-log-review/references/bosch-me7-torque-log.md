# Bosch ME7 扭矩模型 LOG 专项

## 使用条件

用于 ME7 的 KFPED/KFMIRL/LDRXN/KFMIOP、部分负荷点火干预、节气门关闭、扭矩 DTC、TCU 或 ESP 协调
诊断。变量名属于软件族线索；先用当前 HW/SW 的 ME7Info、A2L/DAMOS、FR 或 RAM 地址确认名称、单位、
正负号和采样率。ECUx/第三方工具标签可能把最大值误称为 requested/specified，不以界面英文名代替定义。

## 最低通道组

| 组 | 候选变量 | 要回答的问题 |
|---|---|---|
| 踏板/请求 | pedal、`mrfa/mifa` | 驾驶员和仲裁器实际请求了多少 |
| 负荷 | `rlsol`、`rl_w`、`rlmax/rlmx` | 当前请求、实际负荷和最大包络分别是什么 |
| 扭矩模型 | `mibas`、`mimax`、`misol/miszul` | KFMIOP 的基础/最大扭矩侧与允许扭矩是否一致 |
| 点火路径 | `zwgru`、`zwbas`、`zwsol`、`zwout/zwist` | 最终点火跟随基础、扭矩控制、爆震还是温度修正 |
| 爆震/温度 | 缸别 KR、动态/学习修正、IAT、ECT | 点火波动是否来自爆震、暖机或温度 |
| 空气/增压 | 节气门、目标/实际增压、WGDC、环境压力 | 负荷没有实现是限制、泄漏、过冲还是执行器饱和 |
| 燃油 | 目标/实测 Lambda、喷油脉宽/duty、低高压燃油压力 | 空气和扭矩判断是否建立在可控供油上 |
| 下游 | TCU 降扭请求、档位、换挡状态、ESP/ASR 状态 | 干预来自发动机内部还是外部请求 |

找不到候选变量时，不编造地址；记录工具可提供的等价物并将缺失项标 `UNKNOWN`。

## 诊断顺序

1. **数据质量**：同一时基、采样率足够、单位和标签已确认。
2. **空气/燃油门禁**：MAF/MAP 未封顶，Lambda 跟随，燃压和喷油余量可用；否则先修空气/燃油链。
3. **请求与包络**：比较 `rlsol` 与 `rlmax/rlmx`；最大包络不是当前请求，不要求两者重合。
4. **实际负荷**：比较 `rl_w` 与 `rlsol`，并结合节气门、增压和 WGDC 判断限制或执行误差。
5. **模型与许可**：时间对齐 `mibas/mimax/misol/miszul`；不以单一最大偏差或一次插值穿越判故障。
6. **点火来源**：比较 `zwgru -> zwbas -> zwsol -> zwout/zwist`，同时加入爆震、暖机、IAT/ECT 修正。
7. **下游验证**：看换挡、TCU 请求和 ESP/ASR；部分负荷快速点火微调可能正常，持续振荡或安全反应不正常。

## 测试工况

按风险从低到高：

1. 热态稳定怠速；
2. 固定转速轻负荷巡航；
3. 1500–3000 rpm 缓慢增加踏板；
4. 废气门开始建立增压附近；
5. 中负荷稳态；
6. 短时高负荷；
7. 热浸后重复高负荷；
8. 换挡与 ESP/ASR 受控验证。

没有封闭道路、台架或安全测试条件时，不主动制造 ESP 介入；使用已有事件 LOG 或合规测试环境。

## 裁决与停止条件

| 观察 | 裁决 |
|---|---|
| 部分负荷短时 `zwout` 跟随 `zwsol`，无振荡/DTC | 可为正常快速扭矩控制，继续确认来源 |
| `rl_w` 未达 `rlsol` 且节气门/WGDC 饱和 | 先查空气路径或硬件能力，不改 KFMIOP 掩盖 |
| `rlsol` 被最大负荷侧压住 | 查 LDRXN 与其他包络/修正，不能把包络变量当请求变量 |
| 巡航持续点火振荡、燃油修正发散或失火 | `LOG_FIRST / MODEL_REVIEW`，回退最近模型改动 |
| 节气门强制关闭、扭矩控制上限 DTC、limp 或独立安全监控触发 | `STOP / NO_EDIT`，恢复已知良好版本 |
| TCU 换挡滑摩、异常冲击或 ESP 减扭粗暴 | `STOP / ECU_TCU_MODEL_MISMATCH` |
| KFMIZUOF/KFMIZUFIL 等被写满/拍平后现象消失 | 不算修复，判 `REJECT_MONITOR_DISABLE` |

## 输出要求

- 分开写 `OBSERVED` 通道事实、`INFERRED` 控制解释和 `UNKNOWN` 缺口。
- 报告出现问题的时间、RPM、负荷、档位、温度、持续时间和重复性。
- 下一版动作优先回到根因 MAP/轴/共享对象；不通过扩大闭环权限、关闭监控或低报扭矩让 LOG 好看。
- 没有同版本定义、基准 LOG 和回退条件时，状态保持 `LOG_FIRST / NO_EDIT`。
