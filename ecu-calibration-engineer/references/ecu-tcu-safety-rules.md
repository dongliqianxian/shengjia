## 写入前规则

涉及实际写入 ECU/TCU 前，必须提醒用户：

1. 备份原厂 Flash。
2. 备份 EEPROM / coding / immobilizer 相关数据，视 ECU/TCU 类型决定。
3. 保存读取工具、协议、硬件接口、读写日期和电源条件。
4. 使用稳定电源，避免低电压写入。
5. 校验 checksum，不覆盖 ori 文件。
6. 首次写入后先读故障码，再做低负荷路试，最后做 WOT LOG。

## 标定安全边界

| 风险 | 禁止做法 | 正确做法 |
|---|---|---|
| 扭矩模型 | 只拉高请求，不匹配模型和监控 | 请求、限制、模型、监控一致性检查 |
| 爆震 | 为了马力盲目加点火 | 依据油品、IAT、Knock LOG 小步调整 |
| 空燃比 | 高负荷过稀 | 按发动机类型和温度控制安全 Lambda |
| 排温 | 高转高负荷无 EGT 验证 | 根据 Lambda、点火/SOI、增压控制排温 |
| 涡轮 | 超出效率区硬拉压力 | 看 WGDC/VGT、IAT、背压、实际压力 |
| 轨压 | 大幅提高轨压掩盖喷油不足 | 小幅验证泵和喷油器能力 |
| 变速箱 | ECU 提扭但 TCU 不匹配 | 检查挡位限扭、TCC、压力和油温 |
| 保护逻辑 | 关闭关键保护 | 保留保护，必要时一致性匹配 |

## 排放与合规边界

涉及 EGR、DPF、SCR、三元催化、OPF/GPF、后氧、AdBlue 等排放系统时：

- 以合法合规和机械安全为前提。
- 不提供违法规避、删除、屏蔽、作弊方案。
- 可以分析合法维修、故障诊断、原厂功能逻辑和合规标定边界。
- 如果用户目标可能违法，转向解释风险、诊断方法和合规替代方案。

## 文件管理

| 文件类型 | 要求 |
|---|---|
| 原厂文件 | 必须保留 ori / stock / backup，不覆盖 |
| 修改文件 | 使用清晰命名，包含车型、发动机、ECU、阶段、燃油、日期、版本 |
| Changelog | 记录 Map、区域、幅度、原因、验证结果、下一版方向 |
| LOG | 标明版本、燃油、气温、挡位、路况、时间 |

推荐命名：

`车型_发动机_ECU_阶段_燃油_日期_版本.bin`

示例：

`Tundra_3UR_Denso_HKS_SC_95RON_Stage1_20260527_v1.bin`

## 回退策略

出现以下情况必须建议回退或降低目标：

- 持续爆震修正或多缸退点火。
- AFR/Lambda 明显偏离安全目标。
- EGT 或催化器温度持续异常。
- 增压严重超调、喘振或实际无法跟随。
- 柴油烟度明显超出可接受范围。
- 轨压持续掉压。
- TCU 打滑、TCC slip 高、油温异常。
- ECU/TCU 报扭矩监控、节气门关闭、保护限扭故障。
