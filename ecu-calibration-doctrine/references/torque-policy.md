---

## 第一原则

扭矩模型是**信息节点**，不是**动力节点**。改模型不产生一牛米扭矩，
只改变「谁看到什么数」和「哪个保护触发」。

**三层必须分开：**

| 层 | 是什么 | 典型表 |
|---|---|---|
| ① 模型层 | 对物理事实的**描述** | 正/逆扭矩表、指示扭矩、效率修正链 |
| ② 意图层 | **想要**多少 | Driver Demand、踏板功率请求 |
| ③ 权限层 | **允许**多少 | max torque limiter、许可扭矩、档位扭矩上限 |

**「我要更多动力」属于 ②③，不属于 ①。**
硬件没变、模型是准的却去动模型 = 主动往系统注入谎言。

## Step 1 判架构（决定后面所有做法）

| 架构 | 识别特征 | 做法 |
|---|---|---|
| **分表式** | 正向与逆向功能由不同标定表承担；网格、轴和尺寸可以不同 | 用单位、轴、同版本定义/代码引用和运行信号确认 `F(空气→扭矩)`、`G(扭矩→空气)` 及各自消费者；只有实际物理关系变化或工作域扩展时才讨论联动 |
| **运行时反解式** | 同版本代码证明由正向模型迭代/搜索得到逆向结果 | 按原生算法校正模型；不能仅凭“只找到一张表”就认定自动反解 |
| **分层分表式** | 多组正/逆模型，按模式、档位、温度或效率链激活 | 先查清每张表的生效条件和消费者；遗漏激活分支会造成特定工况跳变 |
| **混合式** | 基础模型叠加点火、λ、摩擦、泵气等效率/损失项 | 先确认修正项参与正算、逆算还是仅用于估算/监控，再决定是否联动 |

**项目案例锚点**：MG1US008（正 0x37BA38 / 逆 0x37BC74，18×14 共用 18 点 RPM 轴）只说明该已验证项目采用分表式结构；地址、尺寸和共轴关系不得外推到其他软件版本。

## Step 2 判是不是真扭矩结构（按证据强度排序）

1. 同版本定义或代码引用证明空气、扭矩变量的输入输出和消费者 ← **最硬**
2. 实车 LOG 能闭合请求扭矩→目标空气→实际空气→估算扭矩链
3. 轴、单位、数值范围和单调性符合物理关系
4. CAN 上有 actual / driver-demand torque，但需确认它是内部控制量还是仅显示/广播量
5. 相似表形态、Nm 轴或密集 MIN/MAX 仲裁只能作为辅助证据

**只有「踏板→目标负荷」、没有 Nm 量 = 负荷结构**，本方法论只能部分套用，不要硬套。

---

## Step 3 三个前置问题（问完才给方案）

1. 硬件改了没？
2. 什么变速箱？
3. 瓶颈是**软件**（limiter 触发）还是**物理**（节气门全开 / 压气机到头 / 爆震在拖点火）？

**瓶颈是物理时，改任何扭矩数字都无效**——先答这一问再谈方案，不要直接开表。
（对应 doctrine §1 原则 1：标定不产生空气）

---

## Step 4 数学（已证明存在功能正/逆关系时）

- 定义 `F(n,air)=torque`、`G(n,torque)=air`。它们是**功能反函数**，不是把单元格做算术倒数，也不保证网格、轴或尺寸相同。
- 先计算 ORI 基线残差：`R_ori(n,T)=F_ori(n,G_ori(n,T))-T`。原厂可能有意保留扭矩储备、损失项和插值偏差，不能把 `R=0` 当成通用目标。
- 只有实测证明目标区域属于近似乘法型物理修正 `F_new≈k·F_old`，并确认效率/损失项没有另行承担该修正时，才可用 `G_new(T)=G_old(T/k)` 作为重采样起点。
- “正表 +10% 对应逆向线性近似 −9.1%”只是教学算例，不是 Stage1 固定配方；非线性区、饱和区和轴外区域不适用。
- 是否从新正表生成逆表取决于软件架构。只有同版本证据证明它们是标定配对时才这样做；运行时反解、共享中间表或分层模型必须沿原生路径处理。
- 网格不一致时，在共同物理域内插值后评价闭合；落在任一表轴外的点必须单独列为 `MODEL_DOMAIN_EXCEEDED`，不能从统计中静默删除。
- **往返自检**同时比较 MOD 与 ORI 的残差、原厂储备和工作域覆盖。`3%` 可作项目目标，不是跨平台硬门槛。
- **数据不足就不改模型**：轮上或道路估算只能提示偏差方向，不能单独证明模型应整体缩放；先补定义、同版本代码或稳定 LOG 网格。
- 岛式修改四周留 1~2 点过渡带。断崖 = 驾驶中的扭矩台阶/顿挫。

## 正模型：改 / 不改

**坚决不动**
- 原厂硬件 + 一阶 + 无台架数据 ← **最常见场景**
- AT / DCT / CVT 且 TCU 依赖上报扭矩
- 自吸车基本任何情况
- 混动 / 48V（HCU 用它做电机分配）
- 只是想解限扭时（该改阈值不是改测量）

**有证据时才动**
- 稳定 LOG、台架或同版本定义证明实际空气→扭矩关系发生系统性变化
- 新硬件把工作点推入原模型未覆盖的空气/扭矩域，且已确认轴不与其他表共享或已完成共享轴影响审计
- 点火、λ、摩擦或泵气效率项发生变化，且代码/定义证明现有修正链不能正确表达

> 换硬件本身不是改正表的充分证据；但若模型确实低报扭矩且不校正，会使 TCU/ESP/监控使用错误扭矩。先证明偏差，再沿原生模型链修正。

---

## 逆模型：改 / 不改

**坚决不动**
- 自吸车 WOT 区（节气门已全开，指令饱和，改了没用还破坏自洽）
- 未做往返自检
- 多层逆表但没搞清激活条件

**可以动**
- 同版本证据证明存在独立逆表，且正向物理模型修正后 ORI→MOD 闭合分析显示必须联动
- 新请求扭矩超出逆模型已验证工作域，需要扩域；先审计共享轴、所有消费者和监控包络

**不能仅为“手感”偏置模型**：踏板响应优先改 Driver Demand（驾驶员需求）或请求整形，不用模型失真换手感。

## 自吸 vs 涡轮：手法差异

| | 自吸 | 涡轮 |
|---|---|---|
| 抬逆表在 WOT | **完全无效**（大气压是硬天花板） | 真的有效（增压能继续升） |
| 主战场 | Driver Demand / 踏板功率请求 | 限制链梳理 |
| η点火 | ≈1，可简化 | 长期 0.85~0.95，必带 IAT 与泵气/背压项 |
| 扭矩上限性质 | 物理给的 | 标定出来的 → 决定「能不能解」 |
| log 取点 | 常规稳态 | **只取稳态点**（转速稳 ≥1s 且目标扭矩变化率≈0）。把迟滞期偏差当模型误差去反拟合 = 经典自毁 |

## 骗扭矩：手法分类与红线

| 类型 | 手法 | 判定 |
|---|---|---|
| **①** | 改阈值（抬 limiter / 许可扭矩表） | 测量仍真实、下游数字仍对 → **这是正路，不算骗** |
| **②** | 压低正模型输出：2a 正表下缩 / 2b 报大摩擦泵气损失 / 2c 压 η点火·ηλ / 2d 动扭矩通道 scaling | 2b·2c 主表看不出改动，是**刻意规避 bin diff** 的手法 |
| **③** | 只骗 CAN 上报值、内部控制不变 | 听起来聪明，**对变速箱伤害最大** |
| **④** | 屏蔽外部降扭请求 | 那条通道上跑的不只是 TCU 换挡降扭，还有 **ESP/TCS 打滑降扭** → **安全问题，不是性能问题** |

**有效性边界**：骗扭矩只对「被软件卡住的涡轮车」有效。瓶颈是物理时无效；
爆震在拖点火时更糟——扭矩不涨，排温和爆震风险都涨。

**代价的本质**：把「可观测问题（车肉）」换成「不可观测问题（离合器微打滑）」。
打滑初期无症状，潜伏几千到上万公里，**交车时一切正常**。

**变速箱敏感度**：CVT（灾难级，钢带打滑直接报废）> 干式 DCT（极高）> AT / 湿式 DCT（高）> MT（无）

### 红线

- **CVT 与干式 DCT 不做，无例外**
- **类型 ④ 不做**
- 类型 ②③ 仅在手动挡或 TCU 已同步刷的前提下考虑，且必须明确告知变速箱风险

### 正路顺序

限制链逐张分类（性能保守型可抬 / 结构保护型须硬件配套）
→ 改阈值不改测量
→ TCU 侧限制就同步刷 TCU
→ 同版本证据证明独立监控镜像/包络确需覆盖新工作域时，保形、保裕量同步
→ 不把某平台的 Level 1/2 干预命名套成通用安全层级
→ ORI/MOD 往返基线对比 + 下游验证

**TCU 不可写的车，「这台车扭矩上限就到这儿」是正确答案，要敢说。**

## 验证顺序（每次都走）

| 步 | 内容 | 判据 |
|---|---|---|
| ① 静态 | 轴、单位、单调性、ORI/MOD 往返残差、储备与轴外区标记 | 不劣化 ORI 闭合；保留已解释的原厂储备；无静默轴外点 |
| ② 空挡 | 怠速目标≈实际、吹转速看跳变 | 偏差 < 5% |
| ③ 稳态路试 | 4~6 转速 × 3 负荷 | 偏差 < 3~5%，点火储备符合预期 |
| ④ WOT | 节气门是否真全开（不全开 = 有限制在砍）、点火储备≈0、排温/爆震/λ | — |
| ⑤ 下游 | 换挡质量、TCS/ESP 介入、巡航是否振荡、仪表瞬时油耗 | — |

> **第 ⑤ 步最容易被跳过，但它是模型不自洽最灵敏的探针。**

## 知识确信度分级（本文专用，**与 doctrine §5 证据等级不是一回事**）

| 级 | 含义 | 内容 |
|---|---|---|
| **A** | 硬事实 / 物理与架构 | 功能正/逆关系需在共同物理域评价；节气门已饱和时，仅抬请求不能突破自吸 WOT 空气上限；无证据不得关闭扭矩监控 |
| **B** | 平台/项目证据成立后可用 | 乘法型模型修正的 `G_new(T)=G_old(T/k)`；TCU 使用 ECU 扭矩量参与压力/保护；ME7 等特定平台的 Level 1/2 干预通道；快慢通道与点火储备 |
| **C** | 经验目标，可调 | 往返残差约 3%、稳态偏差 3~5%、过渡带 1~2 点；必须以 ORI 基线、平台精度和 LOG 重复性校准 |
| **D** | **立场/取舍，不是证据** | CVT 与干式 DCT 红线、类型 ④ 不做、「把可见成本换成不可见成本是坏交易」 |

引用时写全称：「扭矩政策 D 级（立场）」，**不要只写「C 级」**——会和 doctrine §5 的 C 级混淆。
