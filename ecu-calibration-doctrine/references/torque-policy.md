---

## 第一原则

扭矩模型是**信息节点**，不是**动力节点**。改模型不产生一牛米扭矩，
只改变「谁看到什么数」和「哪个保护触发」。

**三层必须分开：**

| 层 | 是什么 | 典型表 |
|---|---|---|
| ① 模型层 | 对物理事实的**描述** | 正/逆扭矩表、指示扭矩、效率修正链 |
| ② 意图层 | **想要**多少 | Driver Demand、踏板功率请求 |
| ③ 权限层 | **允许**多少 | max torque limiter、许可扭矩、档位扭矩上限 |

**「我要更多动力」属于 ②③，不属于 ①。**
硬件没变、模型是准的却去动模型 = 主动往系统注入谎言。

---

## Step 1 判架构（决定后面所有做法）

| 架构 | 识别特征 | 做法 |
|---|---|---|
| **烘焙式** | 一对同 RPM 轴、同尺寸、输入输出对调的表 | 必须成对反方向改 |
| **运行时反解式** | 只有正表，反汇编里有迭代/二分/搜索循环 | 只改正表，逆向自动跟随，不存在「方向」问题 |
| **分层烘焙式** | 多正表配多逆表（如普拉多 7GR：2 正 4 逆） | 先查清每张逆表的激活条件；改一张不改其他 = 特定工况行为跳变 |
| **混合式** | 正表 + 效率修正链（η点火 / ηλ / 摩擦 / 泵气） | 改正表还要逐个检查修正因子是否也参与逆算 |

**案例锚点**：MG1US008（正 0x37BA38 / 逆 0x37BC74，18×14 共用 18 点 RPM 轴）= 标准烘焙式样本。

---

## Step 2 判是不是真扭矩结构（按证据强度排序）

1. 同轴、输入输出对调的表对 ← **最硬**
2. Nm 或 0.1 Nm 为 LSB 的轴
3. map 名含 torque request / max torque limiter / requested engine load
4. CAN 上有 actual / driver-demand torque
5. 反汇编里密集 MIN/MAX 仲裁

**只有「踏板→目标负荷」、没有 Nm 量 = 负荷结构**，本方法论只能部分套用，不要硬套。

---

## Step 3 三个前置问题（问完才给方案）

1. 硬件改了没？
2. 什么变速箱？
3. 瓶颈是**软件**（limiter 触发）还是**物理**（节气门全开 / 压气机到头 / 爆震在拖点火）？

**瓶颈是物理时，改任何扭矩数字都无效**——先答这一问再谈方案，不要直接开表。
（对应 doctrine §1 原则 1：标定不产生空气）

---

## Step 4 数学（成对改时）

- 正表 ×k ⟺ 逆表反方向。严格式是 `G_new(T) = G_old(T/k)`（沿扭矩轴重采样）；
  「Z 值 ×1/k」只是线性区近似，**两端会失效**。
- **正表 +10% 对应逆表 −9.1%，不是 −10%。** 两边都做 ±10% 是错的，会累积系统偏差。
- **逆表不要手改**，从新正表逐行一维反解生成。前提是正表沿充气轴单调——不单调 = 数据有问题，先查数据。
- 轴不对齐（点数或断点不同）必须先插值到共同网格再反解，跳过必引入网格误差。
- **往返自检**：`air = G(t,n) → t2 = F(air,n)`，err < 3% 才算自洽。
  逆表解出的气落在正表轴外时，误差不计入统计但必须单独标记。
- **数据不够只做缩放不改形状**：轮上反推（±5~10%）只能整体/分区缩放；有台架完整网格才准改形状。
  （对应 doctrine §0 无台架限制）
- 岛式修改四周留 1~2 点过渡带。断崖 = 驾驶中的扭矩台阶/顿挫。

## 正模型：改 / 不改

**坚决不动**
- 原厂硬件 + 一阶 + 无台架数据 ← **最常见场景**
- AT / DCT / CVT 且 TCU 依赖上报扭矩
- 自吸车基本任何情况
- 混动 / 48V（HCU 用它做电机分配）
- 只是想解限扭时（该改阈值不是改测量）

**应该动**
- 换硬件后实际扭矩真的变了（机增 / 涡轮 / 凸轮 / 压缩比）
- 有实测证明模型偏了
- 工作点被推到轴外推区（延展轴填值，别依赖 ECU 外推）
- λ 目标大改后 ηλ 不再成立

> **加了硬件却不改正表 = 「被动地骗 TCU」**，和主动骗扭矩后果一样（油压给不够）。
> 这是常见漏做项，机增项目尤其容易犯。

---

## 逆模型：改 / 不改

**坚决不动**
- 自吸车 WOT 区（节气门已全开，指令饱和，改了没用还破坏自洽）
- 未做往返自检
- 多层逆表但没搞清激活条件

**可以动**
- 正表改了之后必须同步反解
- 涡轮中低负荷小幅偏置换手感（须实测确认点火储备没被吃掉）

---

## 自吸 vs 涡轮：手法差异

| | 自吸 | 涡轮 |
|---|---|---|
| 抬逆表在 WOT | **完全无效**（大气压是硬天花板） | 真的有效（增压能继续升） |
| 主战场 | Driver Demand / 踏板功率请求 | 限制链梳理 |
| η点火 | ≈1，可简化 | 长期 0.85~0.95，必带 IAT 与泵气/背压项 |
| 扭矩上限性质 | 物理给的 | 标定出来的 → 决定「能不能解」 |
| log 取点 | 常规稳态 | **只取稳态点**（转速稳 ≥1s 且目标扭矩变化率≈0）。把迟滞期偏差当模型误差去反拟合 = 经典自毁 |

## 骗扭矩：手法分类与红线

| 类型 | 手法 | 判定 |
|---|---|---|
| **①** | 改阈值（抬 limiter / 许可扭矩表） | 测量仍真实、下游数字仍对 → **这是正路，不算骗** |
| **②** | 压低正模型输出：2a 正表下缩 / 2b 报大摩擦泵气损失 / 2c 压 η点火·ηλ / 2d 动扭矩通道 scaling | 2b·2c 主表看不出改动，是**刻意规避 bin diff** 的手法 |
| **③** | 只骗 CAN 上报值、内部控制不变 | 听起来聪明，**对变速箱伤害最大** |
| **④** | 屏蔽外部降扭请求 | 那条通道上跑的不只是 TCU 换挡降扭，还有 **ESP/TCS 打滑降扭** → **安全问题，不是性能问题** |

**有效性边界**：骗扭矩只对「被软件卡住的涡轮车」有效。瓶颈是物理时无效；
爆震在拖点火时更糟——扭矩不涨，排温和爆震风险都涨。

**代价的本质**：把「可观测问题（车肉）」换成「不可观测问题（离合器微打滑）」。
打滑初期无症状，潜伏几千到上万公里，**交车时一切正常**。

**变速箱敏感度**：CVT（灾难级，钢带打滑直接报废）> 干式 DCT（极高）> AT / 湿式 DCT（高）> MT（无）

### 红线

- **CVT 与干式 DCT 不做，无例外**
- **类型 ④ 不做**
- 类型 ②③ 仅在手动挡或 TCU 已同步刷的前提下考虑，且必须明确告知变速箱风险

### 正路顺序

限制链逐张分类（性能保守型可抬 / 结构保护型须硬件配套）
→ 改阈值不改测量
→ TCU 侧限制就同步刷 TCU
→ Level 2 抬许可阈值
→ 往返自检 + 下游验证

**TCU 不可写的车，「这台车扭矩上限就到这儿」是正确答案，要敢说。**

---

## 验证顺序（每次都走）

| 步 | 内容 | 判据 |
|---|---|---|
| ① 静态 | 轴对齐 / 单调性 / 往返自检 / 外推区标记 | err < 3% |
| ② 空挡 | 怠速目标≈实际、吹转速看跳变 | 偏差 < 5% |
| ③ 稳态路试 | 4~6 转速 × 3 负荷 | 偏差 < 3~5%，点火储备符合预期 |
| ④ WOT | 节气门是否真全开（不全开 = 有限制在砍）、点火储备≈0、排温/爆震/λ | — |
| ⑤ 下游 | 换挡质量、TCS/ESP 介入、巡航是否振荡、仪表瞬时油耗 | — |

> **第 ⑤ 步最容易被跳过，但它是模型不自洽最灵敏的探针。**

## 知识确信度分级（本文专用，**与 doctrine §5 证据等级不是一回事**）

| 级 | 含义 | 内容 |
|---|---|---|
| **A** | 硬事实 / 物理与架构 | 反函数互逆关系与 ×k ⟺ ÷k 的数学；自吸 WOT 大气压天花板；TCU 用上报扭矩算离合器油压；EGAS Level 2 独立通道存在 |
| **B** | 行业通行做法 | 快慢通道分离与点火储备；限制链结构；涡轮 η点火 长期 <1 |
| **C** | 经验阈值，可调 | err<3%、稳态偏差 3~5%、轮上反推 ±5~10%、过渡带 1~2 点 |
| **D** | **立场/取舍，不是证据** | CVT 与干式 DCT 红线、类型 ④ 不做、「把可见成本换成不可见成本是坏交易」 |

引用时写全称：「扭矩政策 D 级（立场）」，**不要只写「C 级」**——会和 doctrine §5 的 C 级混淆。
