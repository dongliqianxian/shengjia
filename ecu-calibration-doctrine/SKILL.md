# ECU 标定最高指导原则（Calibration Doctrine）

## 0. 本技能的定位

本技能是**底层逻辑层 / 第一性原理层**，凌驾于所有具体执行技能之上。其他 ECU 技能
（map-analysis、stage1-matrix、log-review、tcu-shift、winols-converter、video-script）负责"怎么做某件事"，
本技能负责"按什么思想、什么顺序、什么判据去做，以及如何交叉验证结论"。

**使用方式**：在执行任何 ECU 标定任务前，先在脑中跑一遍本技能的检查链——确认任务落在标定黄金顺序
的哪一环、适用哪几条铁律、有哪些数值锚点和联动风险——然后再调用对应的执行技能。本技能与用户偏好里
的"三视角分析法"（OEM 工程师 / 改装调教师 / 控制策略师）是同一套体系：三视角是**视角**，本 doctrine
是**方法论与判据**，二者叠加使用。

详细的逐章方法论、确切阈值与公式在 `references/banish-methodology.md`，需要查证某条原则的物理因果或
增压细分时去读它。

## 1. 第一性原理（不可违背的根基）

1. **PCM 不在乎车标。** 处理器只有输入和输出，同一套物理/热力学/燃烧定律对所有发动机一视同仁。
   Bosch / DENSO / Siemens / 独立 ECU 的标定**根本流程完全相同**，只是表名和策略名不同。→ 遇到陌生
   平台不要慌，先映射到"输入→建模→输出"三段，再找对应的表。

2. **标定无法凭空造空气。** 流量上限由机械件决定；标定只能把现有硬件的潜力压榨干净，或毁掉它。→
   任何"加多少马力"的回答都必须先界定硬件瓶颈在哪。

3. **空气流量建模是第一优先级，凌驾一切。** 几乎所有燃油和点火计算都建立在它之上。建模误差直接转化
   为燃油控制误差和工况恶化。**传感器误差与标定误差同等致命。** 误差判据：< 5% 可接受、< 3% 理想、
   OEM < 1%（这就是"±3% Banish 标准"）。

4. **"对了但理由错了"是头号陷阱。** EFI 是层层叠叠的表/标量/函数协同工作；改错地方会治好症状、制造
   新病。每一次修改都必须有物理因果支撑，不照抄经验值。

5. **极限处没有免费午餐（Balancing the Players）。** 同样的功率可由"稀+少点火"或"浓+多点火"达成；区别
   只在离爆震限和燃油系统上限有多近。功率不是单点最大化，而是在安全裕量约束下的取舍。

6. **看负荷，不看 boost。** 进气量上升造成的是负荷漂移而非 boost；boost 只是阻塞度量。判断点火/燃油
   需求永远以 load 为准，不以 manifold pressure 为准。

7. **爆震必须杜绝，没有商量。** 爆震/预燃使峰值压力出现在 TDC 前，破坏力达正常燃烧 2–3 倍。

## 2. 标定黄金顺序（一切方案的骨架）

这是全书最重要的元原则。**任何 Stage 方案、任何 bin 修改、任何 LOG 诊断，都要对照这个顺序检查"是否
跳步"。** 跳步（尤其是没建好空气模型就冲 WOT）是业余与专业的分水岭。

```
①  尽可能多地收集发动机/ECU 信息
②  把精确的组件传递函数写入 ECU（喷油器流量/死区/电压补偿、MAF 曲线）
③  尽量从一个已知良好的标定出发（改动小 = 风险小）
④  尽可能精确地建模燃油输送
⑤  尽可能精确地建模空气流量          ← 花最多时间在这里
⑥  标定部分负荷（part-load）           ← 先这里，不是 WOT
⑦  找到稳定怠速
⑧  确定 WOT 的空气与燃油需求
⑨  确定 WOT 的点火容限                 ← 燃油对了再动点火
⑩  平滑过渡区（cruise↔WOT 的融合）
⑪  检查修正量（闭环 trim 应 < 3%）
⑫  标定瞬态（AE/DE/tip-in/dashpot）    ← 稳态全对之后才做
⑬  实路测试
```

派生口诀：**空气优先 → 先部分负荷后 WOT → 先燃油后点火 → 先稳态后瞬态 → 先基础表后修正/冷启动。**

> **Bench/binary 标定的翻译**：用户主要做台架/文件级标定（WinOLS/ECM Titanium，无 dyno）。黄金顺序
> 在文件标定里翻译为**判断与排序的依据**，而非实测步骤——
> - ②③ → 改件清单核对 + 优先基于 OEM 原厂文件做最小改动（diff 思维）。
> - ④⑤ → 改 boost/torque 前先确认 MAF/MAP 量程不被新流量超限、喷油器 duty 不打满（否则一切下游修改
>   都建立在错误的空气/燃油模型上）。
> - ⑥ before ⑧ → 评估一张 WOT 表的合理性前，先看它与部分负荷区的过渡是否平滑、是否突变（突变=掩盖
>   其他问题）。
> - ⑨ → 点火修改幅度必须以"该负荷下离 MBT/爆震限多远"为锚，而非固定加 N 度。
> - ⑪ → 交叉验证：改完后该平台的 fuel trim / 自学习是否会发散。
> - 校验和（checksum）= ⑬ 的前置闸门：未重算校验和的文件等于未完成。

## 3. 数值锚点速查（拒绝模糊表达的弹药库）

| 量 | 锚点 | 用途 |
|---|---|---|
| 燃烧可行区间 | 8.0:1 ~ 25.5:1 | 超出即失火 |
| 化学计量比 | 14.68:1（λ=1） | 巡航/怠速基准 |
| 负荷分带 | 怠速 10–18% / 巡航 20–30% / 轻加速 30–60% / WOT NA 60–105% / 增压 >100% | 判负荷值是否合理、定位工况区 |
| 峰值火焰速度 | λ≈0.9 | 点火提前最少处 |
| 巡航 λ | 1.00 | 95% 工况 |
| 怠速加浓极限 | λ≈0.85 | 更浓有洗缸风险 |
| WOT NA | **起步 λ≈0.85 → 优化 λ≈0.87** | **起步必须偏浓**（离爆震限远），再向 0.87 收 |
| WOT 增压通用起步 | **λ≈0.77** | 任何增压形式的安全起步值，先浓后收 |
| WOT 离心增压 | 优化 λ≈0.80 | 间冷良好可 0.85；非间冷短时直线加速实测可到 0.89 |
| WOT 涡轮 | 街道/持续负荷 λ≈0.80 | **短时直线加速**可 0.85；持续高负荷必须回 0.80（按 §8 使用工况选） |
| WOT 容积式 | 优化 λ≈0.78 | 跑最热；间冷良好可 0.85 |
| 空气建模误差 | <5% 可 / <3% 理想 / <1% OEM | 第一优先级判据 |
| 爆震超压限 | 允许超压(bar)=RPM/1000 | 4000rpm→4bar |
| EGT 上限 | ~870°C (1600°F) | FI 耐久红线 |
| 铸铁发橙 | ~700°C (1300°F) | 目视温度参照 |
| 点火趋势 | 随负荷↓、随转速↑ | 点火表形态自检 |
| MBT 锚（CA50） | CA50 5–12° ATDC、峰压 7–15° ATDC | 判点火是否在 MBT 附近 |
| 喷油器 duty 上限 | 稳态 <85%（打满即强制变稀） | 空气-燃油链必查 |
| 燃油系统选型 | power×BSFC(≈0.5 lb/hp-hr)=总流量，留 20% 余量 | 喷油器/泵选型（airfuel.py fuel_system_sizing）|
| FI 起步安全裕量 | 离爆震限 ≥3° | WOT 标定缓冲 |
| Nitrous 化学计量 | N2O+汽油 ≈7:1 | 加权算目标比 |
| Nitrous 点火回退 | 2°/50hp 起步 | 介入点附近 |

**点火表 = VE 表的逆，平滑无突变。** 任何一张燃油/点火/λ 表在 3D 下若出现尖锐断层，几乎一定是在掩盖
其他问题（AE 不足、点火错标、传感器越界），先查根因再下结论。

## 4. 三大权衡的固定推理链

任何涉及功率/混合/点火的结论，按这三条链推导并交叉验证：

**A. 空气-燃油链**：进气模型准吗？→ MAF/MAP 量程够吗、是否 pegging？→ 喷油器 duty 是否打满？→ 才谈
λ 目标。任一环错，下游全错。

**B. Balancing the Players（WOT）**：当前在爆震限的哪一侧？→ 要功率是加油换点火、还是减点火换稀混合？
→ 留了多少安全裕量给坏油/热浪/海拔？结论必须给出"为什么是这个幅度而不是更多/更少"。

**C. 负荷-缸压链（尤其 FI）**：boost 变了不等于缸压变了 → 看 load 漂移 → 增压形式决定缸压何时达峰
（离心=红线、容积式/涡轮=峰值扭矩前）→ 决定点火回退的转速分布。

## 5. 联动风险强制清单（每个标定结论末尾必查）

源自方法论 + 用户工程实践，输出任何方案/诊断前逐条核对：

- [ ] **空气模型完整性**：Virtual/Inverse Torque 结构是否需同步改？MAF/MAP 是否被新流量超量程？
- [ ] **TCU 扭矩监控**：AT/DCT 各档扭矩上限是否匹配新扭矩？（不匹配→限扭/顿挫/报错）→ 转 `tcu-shift-calibration`
- [ ] **爆震学习值**：残留是否需清除（注意 data Flash 非易失，断电≠清除，需 ECU Reset）
- [ ] **EGT/CAT 热模型**：保护阈值是否与新功率目标匹配？是否会提前介入拉功率？
- [ ] **VE 偏差 → λ 漂移**：改件后 VE 假设是否仍成立？
- [ ] **Driver Demand 合理性**：踏板→扭矩需求映射是否校验？
- [ ] **空气建模误差 ≤ ±3%**（Banish 标准）
- [ ] **校验和**：checksum/CRC 是否已重算？（未算=文件未完成，常导致 no-start）

## 6. 如何统御其他技能（路由与约束）

调用任一执行技能时，把本 doctrine 作为它的"宪法"叠加进去：

| 执行技能 | 本 doctrine 强加的约束 |
|---|---|
| `ecu-map-analysis` | 拆解单表时必须定位它在"输入→建模→输出"链中的角色（主控/限制器/修正量），并指出它依赖的上游空气模型是否可信。 |
| `air-fuel-model-builder` | 空气建模是第一优先级（原则#3）：任何 load/torque/spark 结论前先确认 VE/MAF 模型 ±3%（Banish）、MAF/MAP 未超量程、喷油器 duty 未打满；先部分负荷后 WOT（黄金顺序④⑤⑥）。 |
| `torque-model-builder` | 建模层另一半（air-fuel-model-builder 的姊妹）：扭矩基础控制结构的**第一性原理方法论**（逆/正扭矩模型、扭矩储备、Level1-3 监控、抬扭须整条路径一致）。**强制空气优先**——逆扭矩模型输出是负荷目标，空气模型不可信先交 air-fuel-model-builder，不在坏空气模型上谈扭矩；各厂命名/限制器顺序交 `oem-strategy-library`，矩阵交 `stage1-calibration-matrix`，代码里找监控例程交 `ghidra-tricore-disasm`。 |
| `closed-loop-control` | 控制层（与建模层平行）：**前馈(开环基础表) vs 反馈(闭环修正)分解**的方法论，落地黄金顺序第⑪步（trim<3%）。核心讲闭环如何吸收/掩盖/对抗基础表改动、trim 归账（把修正搬回基础表）、PID 行为（过冲/windup/权限饱和）、自适应快慢环与清值纪律。前置空气优先（trim 先排除传感器/MAF 误差）；不建 plant（air-fuel-model-builder）、不诊断 LOG（给 `hp-tuners-log-review` 判据）、不出命名（oem-strategy-library）。 |
| `stage1-calibration-matrix` | 修改清单必须按**标定黄金顺序**排序（先空气/燃油后点火、先部分负荷后 WOT）；每项给数值锚点 + Balancing 取舍 + 第 5 节联动清单；功率上限以硬件瓶颈和 ±3% 空气误差为约束。 |
| `hp-tuners-log-review` | 诊断顺序：先判空气模型（MAF pegging/duty 打满）→ 再判 Balancing（爆震 vs 扭矩干预）→ 再判保护策略距阈值多远。用"20-30° 怠速点火摆动=负荷/转速拾取问题"等判据。 |
| `tcu-shift-calibration` | 任何动力侧扭矩提升都要回头核对 TCU 档位扭矩监控匹配（第 5 节第 2 条）。TCU 方法论(换挡点/TCC/油压/档位限扭/扭矩握手五大系统)执行层;bin 里定位换挡点表用其 `tcu-shift-calibration/scripts/tcu_map_locate.py`(递增车速曲线+档位堆叠+升降档回差)。 |
| `tcu-platform-library` | TCU **平台参考层**(类比 oem-strategy-library 之于扭矩):先按**变速箱类型**(液力AT/湿式DCT/干式DCT/CVT/AMT)与具体平台(ZF 8HP/6HP、Aisin、GM 6L-10L、DSG DQ/DL、奔驰 7G/9G、Jatco CVT)定控制架构/自适应机制/访问·checksum 现实/顿挫根因,再回 `tcu-shift-calibration` 调五大系统。**类型不同控制机构完全不同**(同"顿挫"根因不同);改硬件/油压后必清自适应(同 `closed-loop-control`§5);子型号细节标 ✅/🔷/❓ 不当事实;字节交 bin 引擎(经 `multi-vendor-ecu-engine` 核定)、checksum 交 `checksum-crc-engine`。 |
| `winols-scaling-converter` | 换算服务于"组件传递函数精确写入"（黄金顺序②）和 MAF Scaling 技术；缩放时记住"MAF/喷油器/排量同系数、不动死区电压补偿"。 |
| `ecu-video-script-writer` | 口播文案不得为传播牺牲工程严谨；可简化术语但不得违背第一性原理（如不得宣称"加 boost=加缸压"）。 |
| `denso-bin-engine` | DENSO 专有固定编码的字节读写/diff；checksum 不重算，交付前必须经 ECM Titanium / `checksum-crc-engine`。 |
| `toyota-pedal-tuner` | 基于 `denso-bin-engine` 的踏板专项：定位/解码丰田 Lexus DENSO 踏板特性曲线（1×16 uint16 LE, raw/256=%），轻踏板变换（K=0.25 自适应锥度）；只改响应不改峰值功率，WOT 恒 100%；checksum 交 ECM Titanium Auto-Fix。 |
| `bosch-conti-bin-engine` | Bosch/Conti 及多数供应商的 A2L 线性编码（phys=raw×factor+offset）字节引擎；默认 little-endian，仅在 `multi-vendor-ecu-engine` 判定 SH/PowerPC 大端核时切 big；checksum 多层/签名，交付前交工具。 |
| `multi-vendor-ecu-engine` | 先按 MCU 核定字节序（原则#1：PCM 不在乎车标）再解码：TriCore/C167=小端，SH/PowerPC=大端；只做识别与路由，字节工作转给 bin 引擎。 |
| `checksum-crc-engine` | 交付前置闸门（黄金顺序⑬）：只重算可计算的数据块 sum/CRC；EDC17/MED17/MD1/MG1 多层+RSA 签名一律转 WinOLS 插件 / 刷写工具，不得宣称已可刷写。 |
| `ghidra-ida-setup` | 反汇编前置（黄金顺序①）：先定 MCU/架构/字节序/镜像基址/内存映射，用复位向量+字符串校验加载正确，再分析。 |
| `ghidra-tricore-disasm` | 无 DAMOS 找表 + 读限制器/扭矩监控逻辑；地址必须给"如何确认"（xref 路径+轴单调+解码落带），不得只给地址；优先重标定阈值表而非 NOP 掉保护逻辑。 |
| `blind-map-finder` | 无定义(无 A2L/DAMOS/OLS)盲扫 map 候选地址：数据驱动统计扫（单调轴/平滑Z块/指针表/熵分区），只出**排序候选+可信度**不出事实；反汇编印证交 `ghidra-tricore-disasm`、解码交 bin 引擎、功能判定交 `ecu-map-analysis`、换算交 `winols-scaling-converter`。**有定义时不用它**（改 `damos-a2l-parser`/`winols-ols-parser`）。 |
| `damos-a2l-parser` | 解 A2L/DAMOS **文本定义**，提取命名/地址/换算/轴；只产定义元数据，字节工作转 bin 引擎、换算转 `winols-scaling-converter`；地址须判是否需减内存段基址。 |

## 7. 输出纪律（贯穿一切结论）

- **零模糊表达**：禁止"适当/增加一点/略微"。必须给：MAP 名 → 目标区间(RPM×Load) → 修改幅度(%/绝对值)
  → ECU 响应 → 联动影响 → 风险边界。
- **结论前一步步推导，并按第 4 节的链交叉验证合理性。**
- **三视角整合**：OEM（为什么这样设计/保守边界在哪）+ 改装（改哪张表、哪个区间、改多少、为什么是这个
  幅度）+ 控制策略（ECU 如何响应、触发哪些联动、边界条件）。
- 结论末尾附第 5 节联动风险清单中**与本任务相关**的条目。
- 涉及 MAP/方案时用 HTML 色块图（绿=推荐改/黄=谨慎/红=禁激进/灰=不建议），坐标与原截图同向同值。

## 8. 使用工况决定热标定（Know Your Load）

**同一台发动机，用途不同，WOT 标定就该不同。** 判据是「在高负荷停留多久」，不是车型标签。

| 使用模式 | 热行为 | 标定含义 |
|---|---|---|
| **短时高负荷**（直线加速、短冲刺） | 热来不及传导，场次间可充分冷却 | 最宽容，可更激进/更稀（λ 可到 0.85 甚至更高） |
| **反复高负荷 + 热浸**（赛道、山路、越野脱困） | 油温水温机舱温度全部稳定在高位 | **重点看 EGT**；可能牺牲功率、略加浓降温；点火**必须保持接近最优** |
| **持续满载**（长坡拖挂、船机、极速） | 无间断，缸内热量只进不出 | 最严苛：加浓 + **可容忍范围内的最大点火提前**；冷却系统常需升级 |


> **⚠ 本工作流默认工况已锁定** —— 用户实际业务**没有直线加速场景**：
> **默认按「反复高负荷 + 热浸」到「持续满载」侧取 λ 与 EGT 裕量。**
> 「短时高负荷 / 直线加速」一档**不得作为默认取值**，仅在用户就该项目**明确说明**时才启用。
> 未说明用途时直接按**持续满载**侧取值（保守方向），**不必反复追问**。

> **用户主力车型（坦途 / LC300 / 普拉多 / Hilux）的实际热负荷模式接近「反复高负荷 + 热浸」到
> 「持续满载」（拖挂、脱困、长坡满载），不是直线加速。** 按直线加速的裕量给这类车做 Stage1，
> 是把裕量用错了地方。选 λ 锚点（§3）时按本节的使用模式取值，不按车型标签取值。

### 8.1 反直觉铁律：**退点火会抬高排温，不是降低**

「保险起见多退两度」在持续高负荷下是**错的**——点火太退 → 部分混合气在排气门打开时仍在燃烧
→ 热量灌进排气道 → 涡轮/歧管/催化器过热。（铸铁发橙 ≈700°C，OEM 耐久红线 ≈870°C，见 §3）

**正确处理链（按序，不可跳）**：

```
排温偏高 → ① 先【增加】点火提前（让燃烧在缸内完成）
         → ② 若先撞到爆震限  → 加浓 λ 约 0.02 一档，回到 ① 再试
         → ③ 仍不达标        → 降负荷目标 / 升级中冷与冷却
```

催化器尤其致命：排温过高熔化载体 → 排气堵塞 → 功率下降 + 排放失效，**不可逆**。

## 9. 无台架现实与降级规则（本体系的可达性边界）

Banish 全书方法建立在「台架稳态保持某一转速/负荷点 + 宽氧实时反馈」之上。
用户**通常无台架、无测功机** → **拿不到稳态网格**。

> **直接后果：只能做整体或分区缩放，不能重塑 map 形状。**
> 凡是需要「逐格修正」的方法，无台架时只能降级为「路试稳态点抽样 + 趋势外推」，
> **且必须在输出里标注为降级方案**。不标注 = 给出了做不到的方案。

| Banish 台架做法 | 无台架降级 |
|---|---|
| 逐 cell 稳态修正 VE/MAF | 路试可保持的稳态点抽样（定档定速）+ 趋势外推；**标注哪些 cell 实测、哪些外推** |
| 台架扫描找 MBT | 不做 MBT 搜索；以「离原厂多远」为锚，小步长 + LOG 爆震回退量验证 |
| WOT 逐点修正 | 单次 WOT 拉升 LOG 回放，按 λ 误差整体缩放，不逐点雕 |
| 对比两条扭矩曲线选点火 | 无扭矩测量 → **不得**声称「这个点火值更有功率」，只能给爆震裕量判断 |

**另外两条必须知道，否则会误判自己的数据**：

- **建模阶段把负荷压在 ≤60%**：过浓久了冲刷缸壁油膜伤活塞环（**洗缸**），过稀抬排温伤气门/歧管/催化器。
- **台架数据 ≠ 整车数据**：开放排气的发动机台架 vs 装了催化器/消音器/尾管的整车，**VE 差异可达 20%**。
  速度密度系统必须用**整车实际硬件组合**标定。

## 10. 建模阶段的操作前提（做空气模型之前必须先做的事）

黄金顺序⑤「空气建模」不是一上来就改表——**先把测量环境固定住，否则等于打移动靶**。
执行层见 `air-fuel-model-builder`。

1. **强制开环**：把闭环使能表推到量程极端（如开环最小节气门设 0%、闭环最低水温设 300°）。
   理由：闭环 PID 的自修正会**与标定者对抗**；开环下「实测 λ 本身就是修正系数」，数学最简。
   大凸轮或加长头段把 HEGO 挪远时，闭环对抗尤其严重。
2. **λ 目标拉平**：把发动机可能运行到的区域**全部**设为同一个目标（建模期常用 λ=1）。
   目标是动的 = 打移动靶。
3. **从 1500 rpm 以上起步，跳过怠速**：怠速是 PCM 最难控的工况，先做等于自找麻烦；
   略高转速也降低熄火风险。必要时可先**锁死点火**助稳定。
4. **热态、稳态**：暖车完毕、启动加浓已退出，水温/油温/缸盖/进气温度稳定，避免其它修正器干扰。
5. **粗调 → 精修**：建模期该用「电锯」不是「砂纸」——发现整体偏 10% 就整条加 10%，看趋势外推省时间。
6. **IAT 补偿必须单独建，不得靠改基础 VE 表**：在 80°F 标好、跑到 50°F 变稀时，
   **改 IAT 燃油修正曲线**；此时改基础 VE 表 → 温度回升后必然变浓。（同理适用于所有修正层）
7. **HEGO 输运延迟（transport delay）**：改长头段/挪氧传感器后，排气到达传感器的飞行时间变长
   （短歧管→长头段约 **+20~30%**）。不同步修正延迟 → 闭环修正与反馈**相位错开** → 自学习值发散。

> **§1 原则#10 的自检信号**：到了精修/融合阶段还需要大幅修改 → **说明前面建模错了或车有硬件问题**。
> 正确动作是**回头查**，不是继续在精修层加补丁。

## 12. 扭矩模型政策（红线层，优先级高于 §2 黄金顺序 ⑨）

> 完整判定流程见 `references/torque-policy.md`；结构方法论交 `torque-model-builder`，
> 矩阵交 `stage1-calibration-matrix`。以下是**不可让步**的部分。

### 12.1 三层必须分开

| 层 | 是什么 | 能不能为了动力去动 |
|---|---|---|
| **①模型层** | 正/逆扭矩表 —— **对物理事实的描述** | **不能。** 它只回答「这么多空气 → 这么多扭矩」 |
| **②意图层** | Driver Demand / 踏板请求 —— 想要多少 | 能 |
| **③权限层** | limiter / 许可扭矩 —— 允许多少 | 能 |

> **「我要更多动力」属于 ②③，不属于 ①。**
> 硬件没变、模型是准的却去动模型 = 主动往系统注入谎言。
> **唯一必须动模型的场景是「现实变了」**（换硬件 / 模型本来就偏），不是「想要更快」。

### 12.2 正模型：改 / 不改

**坚决不动**：原厂硬件 + 一阶 + 无台架数据；AT/DCT/CVT 且 TCU 依赖上报扭矩；自吸车基本任何情况；混动/48V。

**必须动**：加了机增/涡轮/凸轮/压缩比之后实际扭矩真的变了。
> **加了硬件却不改正表 = 被动地骗 TCU**，后果与主动骗扭矩相同 —— 不是「保守」，是另一种错。

### 12.3 变速箱敏感度（决定骗扭矩的后果有多严重）

**CVT（灾难级）> 干式 DCT（极高）> AT / 湿式 DCT（高）> MT（无）**

TCU 按 CAN 上收到的扭矩算夹紧力/油压。报低了 → 油压系统性欠给 → 打滑、烧片。

### 12.4 红线（无例外）

- **CVT 与干式 DCT 不做骗扭矩，无例外。**
- **不屏蔽外部降扭请求。** 那条通道上跑的不只是换挡降扭 —— 还有 **ESP/TCS 打滑降扭**。
  屏蔽它是**安全问题，不是性能问题**。
- **TCU 不可写的车，「这台车扭矩上限就到这儿」是正确答案，要敢说。**
  给不出方案不丢人，给一个会烧变速箱的方案才丢人。

### 12.5 与 §5 联动风险清单的关系

抬扭结论收尾时，§5 里的「TCU 扭矩监控」「Virtual/Inverse Torque 同步」两条**必查**；
判「修正 vs 骗」的铁证见 `torque-model-builder` §6.5（合法的模型修正不需要动独立监控阈值）。

## 13. 逆向纪律（无 A2L/DAMOS 从裸 bin 逆向时的证据门槛）

> 完整展开与实证案例见 `references/re-discipline.md`。以下是铁律。

### 13.1 刻度（scaling / LSB）需要两条独立证据

**至少一条来自固件自身算术**，另一条来自外部权威：

| 类 | 例子 |
|---|---|
| **固件自身算术** | 反汇编里显式的 `/0x400`、`<<3`、`× 常量`；共享的钳制常量 |
| **外部权威** | 厂家维修手册数据、已知变量 scaling、共用同一轴数组的已知表、同平台 A2L |

只有一条 → 标 **`(est.)`**，且**标记必须写进产出文件本身**，不能只在对话里说。

> **不许反向拟合 LSB。** 先选一个让数字变漂亮的刻度、再拿「漂亮」当证据 = 循环论证。
> 实证：5eat 项目给转速轴定 `x/12.8`（理由是「64/5，看起来是个合理的定点除数」），
> 后被推翻，真值 `x/8`，**错了 1.6 倍**。
> 「这个除数看起来合理」不是证据 —— 它只是让你更难发现自己错了。

### 13.2 找常量走原始字节，不走反编译

**反编译 ≠ 反汇编。** 反编译器按设计丢弃字面量池、未引用常量拿不到符号、PC 相对加载变成裸符号名。
**回答刻度/常量问题必须走反汇编清单或原始字节**，不能用反编译产物。

**把数据区当代码反汇编会制造假交叉引用** → 分析前先导出数据区范围让反汇编器跳过。

### 13.3 候选确认

- **指针命中是确认过滤器，不是第五类候选** —— 不要和 axis/zmap/map 平铺输出。
  实证：5eat 的 307 个候选里只有 **38 个**有真指针引用。
- **并列数组的间距就是单个数组的长度**（可用来自检维度）。
- **全是 2 的幂 = 位模式，不是标量。**

### 13.4 功能判定用实验，不用猜

- **扰动法**：改一个值 → 跑同工况 → diff RAM/log → **动了什么，它就影响什么**。
- **零基线陷阱**：先全零 vs 全高两个极端，再逐个二分；不要在一个中间值上试探。

### 13.5 负面结论是终态，不是降级的结论

低 R²、候选分数接近、可信度标记触发时 → 判 **UNCONFIRMED**，要求重新采集，
**不给一个勉强的答案**。

> 与其给一个带三行警告的地址，不如明确说「当前证据不足以定位，需要 X」。
> **带警告的错答案会被使用，明确的「不知道」不会。**

作废的结论**保留原文 + 就地标注推翻依据与时间**，不要删 ——
删掉错误结论 = 丢掉「为什么错答案当初看起来是对的」这个记录。
