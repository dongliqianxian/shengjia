# Bosch MG1 平台（现代汽油直喷增压 / AURIX / MDG1 世代）

MG1 与 MD1 是**同一代硬件、同一套标定容器**，区别只在燃料侧的功能集。
所以 `md1-platform` 里关于 AURIX、RSA、访问难度的结论在这里**同样成立**，本技能不重复，
只写汽油侧特有的东西：**自描述容器的三条坑**、**换算锚点**、**扭矩链闸门清单**。

## 1. 子型号识别

| 变体 | 定位 |
|---|---|
| **MG1CS0xx** | 乘用汽油主力（MG1CS002 / CS008 / CS011 / CS017 …） |
| MG1CP0xx | 部分变体 |
| MG1CS2xx | 高端/多缸（保时捷、宾利等） |
| （柴油 MD1CPxxx / MD1CSxxx） | 不属本技能 → `md1-platform` |

识别来源：字符串区。**MDG1 世代的两条 ID 串位置固定**（实测 MG1CS002）：

```
0x080144   10SWxxxxxx                                    ← 软件号（不同整车会不同）
0x080248   45/1/MDG1/5/P1793//DMG1002AH2C1793_MY19DP6/// ← 工程号 + 数据集 ID
```

> **判同源看第二条，不是第一条。** 实测奥迪 A8 55 TFSI 与大众途锐 3.0 V6 TSI
> 软件号不同（`10SW059262` / `10SW062066`），但**数据集 ID 完全相同** ——
> 标定容器几何、轴、换算、记录布局全部一致，是同族移植可行的前提。
> 文件名不是证据；库匹配交 `ecu-calib-finder`。

## 2. 标定容器 —— 三条必须写死的事实

MG1 是**自描述容器**（每张表自带维度+轴），穷举全表清单交 `bin-to-a2l`。
但汽油侧有三个坑，踩了整表歪：

**① 头布局有两种，由 `RECORD_LAYOUT` 决定，不能假设**

```
交错型    [n1][轴1][n2][轴2][数据]      例 _REC_S3MAP_55_S2_U2_S2（VW 侧 DATA_*_VW 段）
计数在前  [n1][n2][轴1][轴2][数据]      例 RB_Map_S16U16_U16 / RB_Map_U16U16_U16（Bosch 段）
一维曲线  [n][轴][数据]                 例 RB_Curve_U16_U16
```

同一份 bin 里两种并存。假设一种、按 ±2 字节去凑，会整表歪一格。

**② A2L 的 CHARACTERISTIC 地址 = RECORD 起点（`NO_AXIS_PTS` 那个字），不是数据首字节**

**廉价自检：同族相邻对象的地址间距 = 记录总长（头+轴+数据）。** 对不上就是起点错了。

**③ `ROW_DIR` / `COLUMN_DIR` 决定哪个轴变化快 —— WinOLS 显示的行列方向可能是转置的**

判方向最快的办法：**两种读法各画一遍，物理上单调/平滑的那个才是对的。**

## 3. 汽油侧换算锚点（MG1CS002 实测，可直接当候选试）

| 量 | factor | 备注 |
|---|---|---|
| 转速 | ×0.25 或 ×0.5 | 两种都常见，看 COMPU_METHOD |
| 相对充气量 rl | **×0.0234375**（3/128） | % ；>100% 即增压 |
| 扭矩 | ×0.1 Nm | VW `DATA_*_VW` 段用 **×0.09765625**（100/1024） |
| 压气机压比 | **×1/8192** | 无量纲 |
| 增压压力 | ×0.078125 hPa | 大气压轴 ×0.0390625 hPa |
| λ | ×1/4096 | |
| **点火** | **SBYTE ×0.75°** | ⚠ 见下 |
| 相对百分比 | ×100/65535 | |
| 温度 | ×0.1 − 273.14/273.15 | |
| 功率（PwrCls） | ×0.01 kW | 32 位 |

> ⚠ **点火必须按 SBYTE 读。** 按无符号读会看到 `254 → 0` 这种"回绕"，
> 实际是 **−1.5° → 0°**，一个干净的 `raw += 2`。误判成溢出会让你以为程序写坏了。

## 4. 汽油扭矩链 —— 闸门清单（EA839 实测，跨 MG1 通用）

MG1 是彻底的**扭矩基础型架构**：一条主链 + 一条**独立的 Level-2 监控链**。

```
主链  踏板 ─▶ DrvDemA 驾驶员需求(②意图) ─▶ LimTqMax(Nm/%) 扭矩仲裁(③权限)
      ─▶ KFMIRL 逆模型 ─▶ 目标充气量 rl ─▶ KFRLXTSRN 充气量上限
      ─▶ 增压控制(目标增压/废气门) ─▶ 实际 rl ─▶ KFMIOP 正模型 ─▶ 上报扭矩 ─▶ TCU/ESP
监控链  MonDrvDemA_* ─▶ MonElmAct_* ─▶ …  逐环镜像校验，超限即跛行
```

**动力上限由链上最紧的那个闸门决定，不是由某一张"动力表"决定。** 实测清单（VW 途锐原厂值）：

| 闸门 | 代表 map | 原厂值 | **副本数** |
|---|---|---|---|
| 声明功率/扭矩 | `PwrCls`（u32，kW/Nm/rpm 三组） | 260 kW / 500 Nm | 5（功率等级 0-4）|
| 驾驶员需求上限 | `DrvDemA_tqCluDemAceped**_M_VW` | 460 Nm | **13** |
| 最大扭矩限制器 | `LimTqMax(Nm)`（轴 = rpm **原值**，非缩放） | 330–450 Nm | **21** |
| 相对扭矩限制器 | `LimTqMax(%)` | 40–72 % | 11 |
| **充气量上限** | `KFRLXTSRN`（vs 进气管温度） | **186.7 %rl ← 真正的硬闸** | 5 |
| 增压绝对上限 | `Limiter of Turbo pressure` | 2550 hPa | 1 |
| 压比上限 | `TurboP#1` / 压比孪生对 | 2.42 / 3.170 | 2 + **2（孪生）** |
| 喘振线 & 旁通阀迟滞 | `BstCtl_ratPCmpr(No)Surge_T` / `CByVlv_ratPCmpr*HysLim_M` | 1.0–2.8 / 1.03–3.9 | 2 + 6 |
| 增压合理性诊断 | `KFFGLDRNP` | 高压比角落门限 1.0 | 1 |
| 点火 | 8 张（含各凸轮/气门变体） | SBYTE ×0.75° | 8 |
| 热保护 | `ExhMod_tExhVlvHomB1_M` 排温模型 | 顶到 989 °C | 2（市场变体）|

### 4.1 MG1 最容易翻车的三件事

**① 副本极多（2–21 份）。** 按功率等级 / 驾驶模式 / 市场变体 / 监控镜像分。
**改一份等于没改，漏一份等于埋雷。** 实测某商业参考程序自己就漏了两处：
监控镜像 11 份只改 10 份、压比上限孪生对只改一半。
→ 齐全性必须扫，交 `parallel-map-finder`；**用共享轴的字节签名扫描最省事**。

**② 监控层是独立的一整套（`Mon*` 家族）。** 这是 MDG1 相比老平台最大的结构差异。
主路抬了监控不抬 → 跛行；主路抬了把监控**拍平** → 保护没了。**正确做法是保形同步抬。**

**③ 热域才是真边界，扭矩不是。** 排温模型顶到 989 °C。
商业程序普遍把它整体下调（实测 ×0.962）来推迟保护介入 ——
**这是最常见也最危险的捷径**，对"反复高负荷 + 热浸"工况（拖挂/越野/长坡）尤其致命。
判据见 doctrine §8 使用工况 与 §12.1 三层分离（排温模型属①模型层，不为动力去动）。

### 4.2 一阶实际能到哪（B 级）

EA839 3.0 V6（原厂 340 PS / 450–500 Nm），硬件全原厂或只换头段：
**约 390–415 PS / 550–580 Nm**，扭矩平台约 1500–5000 rpm。
程序里声明的 kW（`PwrCls`）**通常乐观于实测**，不要拿它对客户承诺。
限制因素按序：涡轮本体流量 → 中冷 → 排温 → 变速箱扭矩容量。

## 5. 访问与 checksum 现实

与 MD1 相同（细节见 `md1-platform` §3）：

- **AURIX + RSA secure-boot**。cal 区 CRC 可算，**引导签名本地伪造不了**。
- **本地算通 CRC ≠ 可刷。** 交付必须明写"文件当前不可刷"，
  由 **KESS3 / AutoTuner / PCMFlash 写入时处理**，或先过 **WinOLS 的 MG1 插件**。
- 刷后必须 **ECU Reset 清爆震学习值**（Data Flash 非易失，断电 ≠ 清除）。
- **TCU 不在 ECU 文件里**（VAG 多为 ZF 8HP / DQ）。抬扭必须同步 TCU 各档限扭，
  不同步 = 打滑 / 烧片 → `tcu-platform-library` + `tcu-shift-calibration`。

## 6. 三条不能碰的线

1. **低转速（1200–2500 rpm）不加点火** —— LSPI 禁区，见 doctrine **§15**。
   原厂 +1.5° 只给 `rpm ≥ 2000` 且 `负荷 ≥ 120 %rl`，照抄这条边界。
2. **不下调排温模型** —— 让 ECU 少报排温 = 把热保护往后推（§4.1 ③）。
3. **不为动力去动 KFMIRL / KFMIOP** —— 模型层。实测 `KFMIRL` 顶列请求
   200–236 %rl，**本来就高于许可**，抬它在 WOT 不产生任何效果，
   却会让**外部降扭请求（ESP/TCS/TCU）被打折**。要更多空气去抬 `KFRLXTSRN` 和增压目标。

## 8. 边界（写死，别承诺）

- 本技能只做**平台识别 / 容器事实 / 闸门清单**，不出具体修改数值（交矩阵技能）。
- 第 4 节的副本数与原厂值来自 **MG1CS002 / P1793 / EA839 实测**，是 **A 级**；
  推广到其它 MG1 子型号是 **B 级推断**，每台车必须用自描述头重新核实副本数量。
- 换算锚点是**候选**不是事实 —— 没有 A2L 时必须用物理量程反证（doctrine §14）。
- 不判"多份平行表哪份在什么条件下生效" —— 静态分析给不了，要 LOG。
