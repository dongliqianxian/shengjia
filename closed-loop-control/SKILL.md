# 闭环控制逻辑(Closed-Loop Control)

## 0. 本技能的定位

三层里的第三层——**控制层**,与建模层平行:

```
被控对象模型(plant)   air-fuel-model-builder     VE/MAF/喷油器 → 空气、脉宽
扭矩控制结构           torque-model-builder       扭矩 ↔ 负荷 ↔ 空气 互译与仲裁
控制层(feedback)      closed-loop-control  ←本    基础表(前馈) + 闭环修正(反馈) 如何协同/打架
```

它实现 doctrine 黄金顺序第 ⑪ 步("检查修正量,闭环 trim 应 <3%")的方法论:**标定的终态是让闭环
几乎无事可做——修正搬进基础表,而不是让闭环长期替你顶着。**

---

## 1. 第一性原理:每个被控量 = 前馈基础表 + 反馈修正项

ECU 里几乎每个闭环受控量都是这个结构:

```
命令值 = 前馈(开环基础表, feedforward)  ×/+  反馈修正(闭环, feedback)
                    │                              │
             标定的主战场                    传感器误差/老化/环境的即时补偿
```

- **前馈(feedforward)**:基础表先把命令送到"接近对"。这是你标定要改的地方。
- **反馈(feedback)**:闭环用传感器测实际值,补掉前馈的残差。它是"创可贴",不是"手术"。

**判据:一个健康的标定,闭环修正应当小(doctrine:<3%)。** 闭环长期大幅修正 = 基础表错了,
去修基础表,别加大闭环权限硬扛。

**四个典型闭环:**
| 闭环 | 传感器 | 前馈基础 | 反馈修正 | 开环退出条件 |
|---|---|---|---|---|
| 燃油(λ) | O2/宽氧 | 基础喷油/VE | STFT+LTFT | WOT/冷机/加速加浓 → 开环 |
| 增压 boost | MAP/boost 传感器 | WGDC 基础表 | boost PID | 部分负荷不建压 |
| 爆震 | 爆震传感器 | 基础点火表 | 爆震回退+学习 | —— |
| 怠速 | 转速 | 怠速空气/点火基础 | 怠速 PID(空气+点火快通道) | 离开怠速窗口 |

---

## 2. 头号陷阱:闭环会吸收 / 掩盖 / 对抗你的基础表改动

这是本技能存在的核心理由。改基础表时闭环在后台反应,必然遇到:

**① 吸收(改动"看起来没生效")**
改了 VE/基础燃油,λ 闭环立刻反向调 STFT 把 λ 拉回目标 → 稳态输出没变,你以为白改了。
**真相**:改动生效了,只是闭环把它吃进了 trim。看 trim 变化,不只看最终 λ。

**② 双重计数(改完过浓/过稀)**
LTFT 已经 +15%(基础燃油偏稀 15%),你又在基础上加 15% 燃油 → 总量 +30%。
**正确**:先把 LTFT 归账进基础(§3),让 LTFT 回 0,再谈其它改动。

**③ 掩盖(危险)**
爆震闭环长期回退 4°,车"没爆震"是因为闭环在救。你若只看"无爆震"就以为基础点火安全 → 一旦
闭环权限用尽(热浪/坏油/高负荷)立刻爆震。**看闭环修正量,不只看被控量本身。**

**④ 对抗(震荡)**
两个闭环或前馈/反馈争同一个量(如 VE 自学习 vs 燃油 trim),或 PID 增益不当 → hunting。

**方法论口诀:改基础表前先读闭环修正量;改完看闭环修正是否回落到 ~0;闭环大 = 基础错。**

---

## 3. 燃油 trim 归账(本技能最实用的工具)

**目标:把闭环长期顶着的修正搬回基础表,让 LTFT 回 0。** 这是"修正量 <3%"落地的具体算法。

```
总修正 = STFT + LTFT           (都是相对基础的百分比)
新基础 = 旧基础 × (1 + 总修正/100)
```
- 燃油 trim **为正 = ECU 在加燃油 = 基础偏稀 = 基础要上调**;为负反之。
- 搬完后,理论上 LTFT/STFT 应回到 ~0(闭环无事可做)。
- **前提(doctrine 空气优先)**:trim 必须先排除传感器/进气泄漏/MAF 误差,否则你把一个测量错误
  焊死进了基础表。宽氧比窄氧可信;WOT 段是开环,不受 trim 影响,要单独用宽氧标。

`scripts/control_loop.py reconcile` 做这个计算并给残差预期。

## 4. PID / 闭环行为(理解 boost 与怠速闭环)

boost 闭环、怠速闭环本质是 PID(前馈 + P/I/D)。标定要认得这些行为:

- **P(比例)**:响应误差,太大→震荡,太小→迟钝、稳态误差大。
- **I(积分)**:消稳态误差,太大→过冲 + 震荡 + **积分饱和(windup)**。
- **D(微分)**:抑制过冲,对噪声敏感。
- **积分饱和 windup**:执行器已到极限(WGDC 100%)但仍未达目标,积分项继续累加,等达到后严重过冲。
  好的实现有**抗饱和(anti-windup)**。boost 欠增压后猛过冲常是 windup。
- **权限饱和(authority)**:闭环输出被 clamp 限死(如 boost PID ±X%)。基础前馈太离谱,闭环权限不够
  补 → 达不到目标。抬 boost 要同时保证前馈 WGDC 够接近,别让闭环独扛。
- **hunting(震荡)**:增益不当或两环打架,被控量周期性摆动。

标定含义:boost 过冲/迟滞/震荡,先分清是**前馈基础表不准**(闭环长期大修正)还是**PID 增益/权限**问题
——前者改基础 WGDC 表,后者调增益/权限。`scripts/control_loop.py pid` 演示这些行为。

## 5. 自适应 / 学习(Adaptation)与清值纪律

闭环有快慢两级:**快环(STFT)**即时波动,**慢环(LTFT / VE 自学习)**把持续偏差固化进**掉电不丢的
data flash**。

- 快环修正持续偏一个方向 → 慢环逐渐吸收,快环回到 ~0 波动。总修正守恒,只是从短期迁到长期。
- **清学习值纪律(doctrine 联动清单)**:改了基础表 / 改了硬件后,残留的学习值是针对旧状态的,会
  与新基础打架 → 需要清。**注意 data flash 断电≠清除**,得走 ECU Reset / 工具清适应值。
- 清完后闭环要重新学习一段,期间快环(STFT)先顶着,LOG 会看到 STFT 变大再慢慢回落——这是正常收敛。

`scripts/control_loop.py adapt` 演示快→慢迁移与"清值后快环重新顶起"。

## 5.5 输运延迟(transport delay)——闭环发散最容易被漏掉的物理原因

闭环不是"读到偏差立刻改"，ECU 按**排气从气门到氧传感器的飞行时间**决定何时把修正对应回哪一次喷射。

- 改**长头段 / 挪氧传感器位置**后，这个飞行时间变长（短歧管→长头段约 **+20~30%**）。
- 不同步修正延迟 → 闭环修正与反馈**相位错开** → 修正打在错的循环上 → **学习值向偏离方向发散**，
  表现为 LTFT 长期漂移却怎么归账都回不到 0。
- 判据：基础表已按 §3 归账、空气模型也确认过，LTFT 仍系统性漂移 → 查排气几何是否改过。
- 另有两种情况会让闭环根本不该开：氧传感器挪太远即使带加热也到不了工作温度；
  大凸轮大重叠角低速扫气把新鲜空气推到传感器 → 读数失真。此时应**提高闭环使能转速门槛**，
  或干脆全时开环。

## 6. 脚本:scripts/control_loop.py(第一性原理,可自测)

```bash
python scripts/control_loop.py --selftest
# 燃油 trim 归账:基础脉宽 3.0ms, LTFT+12% STFT+3% → 新基础 & 预期残差
python scripts/control_loop.py reconcile --base 3.0 --ltft 12 --stft 3
# PID 阶跃:对比良好整定 vs 高积分无抗饱和(看过冲/windup)
python scripts/control_loop.py pid --setpoint 0.7 --kp 2 --ki 3 --kd 0.1
# 自适应迁移:快环修正如何迁入慢环学习
python scripts/control_loop.py adapt --bias 8
```

诚实边界:PID 用一阶滞后 plant 的**通用演示模型**,只回答"行为/趋势对不对"(过冲、windup、
权限饱和、收敛),**不是**你 ECU 的实际增益或 plant——具体增益/权限/使能条件是标定表,解码交 bin 引擎、
拆解交 `ecu-map-analysis`、命名交 `oem-strategy-library`。trim 归账假设修正是纯乘性燃油修正。

## 7. 与其他技能的关系

```
closed-loop-control
├── 前置(空气优先): trim 先排除传感器/MAF/进气泄漏误差 ← air-fuel-model-builder
├── trim 归账后校 VE/基础燃油 → air-fuel-model-builder(用闭环输出修 plant)
├── 闭环在 LOG 里的读法(STFT+LTFT 求和/boost 误差/爆震回退) → hp-tuners-log-review(本技能给它判据)
├── 怠速闭环的目标定位 → idle-speed-calibration
├── boost 前馈基础表/负荷链 → torque-model-builder + oem-strategy-library
├── 闭环增益/权限/使能表的字节定位与解码 → blind-map-finder / ghidra-tricore-disasm / bin 引擎
├── 各厂闭环表命名 → oem-strategy-library
└── 所有结论经过 ecu-calibration-doctrine
```

## 8. 输出纪律

- 任何被控量先分解成**前馈基础 + 反馈修正**,指明"你要改的是哪一半"。
- 改基础表的建议必须附**闭环反应预期**(trim 应回落 / 需清学习值 / 别让闭环独扛)。
- "无爆震/λ 达标"不等于安全——必须核对**闭环修正量**是否在健康区(<3%),否则闭环在掩盖问题。
- trim 归账前先声明"已假定 trim 非传感器误差"(空气优先),否则会把测量错误焊进基础表。
- 具体增益/权限/使能条件/命名不由本技能出(交 ecu-map-analysis / oem-strategy-library);本技能出**控制论结构与因果**。
